# 产品融合与仓库整理记录

## 决策基线

本轮融合以最大化产品功能为目标，采用以下已确认决策：

1. FastAPI 是唯一产品后端；
2. 所有科研运行必须登录，暂停公开注册，仅允许服务器管理员建号；
3. “我的画像”与明确标识的“演示画像”并存；
4. 同时开放离线规则、服务器免费 DeepSeek 和 BYOK；
5. 运行结果默认保存，论文原文只有在用户明确同意后保存；
6. 完全停止维护旧离线网页版本。

## 产品理念

- 证据先于主张：接受关系必须回到论文、章节和字符跨度；
- 多智能体是裁决机制：提出、批判和裁判的分歧及理由必须可见；
- 图谱是计算底座：检索、路径解释、推荐、时间线和研究想法应复用同一证据图；
- 个性化形成闭环：画像影响诊断与资源，反馈驱动下一轮难度和解释策略；
- 复现属于产品能力：run 标识、模型、画像版本、证据快照和实验协议共同形成审计链。

## 融合结果

React 前端保留原有学术编辑风格，并接入账号门禁、画像编辑、模型选择、SSE 轨迹、反馈、在线候选检索、运行留存和完整证据图谱。原 React 产品线中的论文摄入和实验账本继续保留。

PyQt6 桌面端作为第二种产品客户端恢复，但不恢复旧离线执行方式。桌面端通过共享 API 客户端登录 FastAPI、读取领域/画像/模型目录并消费真实 SSE，不能绕过账号、留存和密钥规则。

FastAPI 统一提供账号、画像、模型、运行、流式运行、反馈、摄入、图谱、在线检索、历史与实验接口。错误响应统一为 `error.code / error.message / error.retryable`。Cookie 会话使用 `HttpOnly + SameSite=Lax`；生产 HTTPS 应设置 `YANHAI_COOKIE_SECURE=1`。

旧 `web/` 和 `server.py` 已移入历史归档，不再由命令行入口、Docker、systemd 或 Nginx 引用。

本地 Python 工具统一使用根目录 `.venv`。FastAPI、后台脚本、测试、Streamlit 实验台、PyQt6 与 PyInstaller 不再各建环境；React 构建仍使用 Node/npm。CUDA GLiNER 保持远程 GPU 隔离，避免把 Torch/CUDA 塞入主产品环境。

第二轮目录整理把四个 Streamlit 工具统一到 `scripts/实验台/`，配置按 `config/实验/` 与 `config/文献/` 分组。未被产品、脚本或测试读取的旧模型路线配置转入 `docs/归档/配置/`；未被运行时读取的 `outputs/domains/` 派生图谱已删除，避免把可再生成结果误当作产品事实源。

## 数据保护

- BYOK 不进入数据库、结果或日志；
- 免费 DeepSeek Key 只从服务器本地密钥文件读取；
- 每次科研运行保存到当前用户历史；
- 文本论文与 PDF 解析正文默认不持久化；勾选明确授权后才保存正文；
- 演示画像可用于运行，但运行所有权仍属于当前登录用户。
