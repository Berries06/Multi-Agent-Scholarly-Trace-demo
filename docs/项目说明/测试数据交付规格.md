# 测试数据交付规格（9-05 提交口径，评委视角）

> 依据赛题 PDF《XH-202630 比赛方案》评分细则推导，是"测试数据"这项交付物的
> 最低合格线与差距清单。**任何关于测试/案例的讨论先看这张表，不看个人感觉。**

## 1. 评委口径的硬数字（摘自赛题）

| 项 | 要求 | 出处 |
|---|---|---|
| 领域知识库切片 | ≥1 个垂直领域 | 答题要求（五·2·(3)） |
| 学习者学情数据 | ≥2 组（满分档写 ≥3 组）差异化画像 | 答题要求 + 实用价值评分 |
| 完整输入输出示例 | 画像特征 + 多智能体中间数据 + 最终资源 | 答题要求（五·2·(3)） |
| **测试用例数** | **≥50 组**；"不足 50 组或缺乏真实领域数据" → **扣 10–20 分** | 实用价值评分细则 |
| 幻觉率 | **<5%** | 实用价值评分 |
| 画像-难度适配准确率 | **≥85%** | 实用价值评分 |
| 核心知识点覆盖率 | **≥90%** | 实用价值评分 |

## 2. 当前真实差距

| 项 | 要求 | 现状 | 差距 |
|---|---|---|---|
| 领域切片 | ≥1 | 3 领域 ✅ | — |
| 画像 | ≥3 | 3 组 ✅ | — |
| 完整示例 | ≥2 | 9 组 ✅ | — |
| **测试用例** | **≥50 组** | 140 条（L2 已生成，28 正 + 112 负；待 L3 抽查 + 三指标测量） | **数量已过线，性质待 L3 锚定** |
| 三硬指标 | 真实测量 | 代理值（hallucination_proxy_rate 等） | **待 L3 核验后在冻结集上计算** |

**结论：数量线（≥50）已解除；剩余关键是 L3 人工核验锚点与三指标真实测量。**

## 3. 三层用例方案（到 9-04，成本约团队 2–3 小时人工）

| 层 | 数量 | 性质 | 用途 |
|---|---|---|---|
| L1 合成压力池 | 24（已有） | 人工构造噪声 | 开发迭代、消融对照 |
| **L2 真实证据机制用例** | **60–80** | 从 19 篇证据卡的 91 条真实关系**程序化生成**正/负/噪声变体（错误证据 ID、无证据、绝对化改写、类型错配、跨度错位）——基于真实论文证据跨度，不是凭空编造 | **主报告：幻觉率/不支持接收率 + Wilson 区间** |
| **L3 人工核验锚点** | **20–30** | 团队抽查 L2 的自动标签（每条约 20 秒） | gold 精确率/召回、标注一致性 |

- L2 生成脚本：`scripts/generate_decision_cases.py`（**已建**，2026-08-20 生成 v1：140 条 = 28 正 + 各 28 条四类负例，SHA-256 记录在案），种子冻结、生成后只读；
- L3 是"缺乏真实领域数据"这一扣分点的防御：标签由人核过、出自真实论文；
- 三硬指标在 L2+L3 冻结集上统一计算，附数据版本哈希与置信区间；
- 之后每篇新论文进库，L2 自动扩容，案例池随知识库增长。

## 4. 我的保留意见（不同意之处）

1. **不同意"金标准等以后"**：完全双人标注 60+ 条确实来不及，但 L3 的"抽查核验"只要 2–3 小时，必须 8 月底前完成，否则三硬指标没有真实锚点；
2. **50 组只是扣分线不是满分线**：满分档还要求"精准贴合行业实际规范"，意味着至少一个领域需要你们懂行的人做**语义级复核**（不只是对错，还有"抽得全不全"）；
3. 24 条压力池从此**只当开发池**，任何对外数字不再以它为中心。

## 5. 自评（对照 30/25/15/30）

- 完整性 30：当前约 24–26 分（闭环在，测试数据是短板）；
- 创新性 25：当前约 15–18 分（机制完整但"多智能体调模型"未落地，差距 1 补齐前不提分）；
- 体验 15：当前约 10–11 分（React 骨架在，图谱可视化/编排动画缺）；
- 实用价值 30：当前约 15–18 分（**测试用例 <50 组触发扣分线**，三指标是代理值）。
