# C 线第一大任务：模型选型与接入方案（2026-08-23）

> 适用：成员 C（真模型实验与平台线）。前置事实：三家供应商已选定——DeepSeek、Kimi(Moonshot)、智谱 GLM，每账户 ¥50。本方案基于：三家官方模型广场、30 篇新文献与小型团队部署实践调研（见第 3 节依据）、本项目 390 条冻结用例与"精确率≥90% 前提下最便宜"的选型标准。

## 1. 结论先行（照抄即可开工）

1. **选 6 个模型、跑一个"模型×角色"矩阵**：三家 × 各两档（便宜档 + 强档），总预算 ¥150 以内稳够；
2. **便宜档**：`deepseek-v4-flash`、`glm-4-flash`、`kimi-k2.6`（或控制台当前最小档）；
3. **强档**：`deepseek-v4-pro`、`glm-4.5`、`kimi-k2.5`（可再测 k2.5 的 thinking 开/关两种模式）；
4. 矩阵 = 同质组（每模型同时当批判者+裁判，6 组）+ 异质组（便宜批判者×强裁判、强批判者×便宜裁判，约 6–8 组）；
5. 流程：8 条冒烟（R017）→ 390 条全量 → Pareto 图 → 冻结"精确率≥90% 前提下每用例成本最低"组合；
6. 队员复用 Key 的方式与纪律见第 6 节。

## 3. 模型差异要体现什么（调研依据）

从 30 篇新文献与部署实践提炼出五个"差异维度"，矩阵就是围绕它们设计的：

**维度 1：成本阶梯（便宜档 vs 强档）→ 回答"多花一倍钱值不值"。**
依据：FrugalGPT（级联降本 98%，[arXiv:2305.05176](https://arxiv.org/abs/2305.05176)）、RouteLLM（95% 质量换 85% 成本下降，[arXiv:2406.18665](https://arxiv.org/abs/2406.18665)）、CrewAI 官方按角色分模型指南（[docs.crewai.com](https://docs.crewai.com/v1.15.5/en/learn/llm-selection-guide)）。**做法**：同一家内部就存在 flash 与旗舰两档，交叉比较后画 Pareto。

**维度 2：厂商异质（DeepSeek vs Kimi vs GLM）→ 回答"异质裁决是否降低盲区相关性"。**
依据：MasRouter（按任务目标路由异构 LLM 优于单一大模型，[ACL 2025](https://aclanthology.org/2025.acl-long.757/)）、MoA（多模型协同超单模型，[arXiv:2406.04692](https://arxiv.org/abs/2406.04692)）。**做法**：同档跨厂商配对（如 glm-4-flash 批判者 × deepseek-v4-pro 裁判），验证异质组合是否比同质组合在相同成本下错误更少。

**维度 3：推理深度（thinking 开/关）→ 回答"裁判需不需要'思考'"。**
依据：Kimi k2.5 双模式；SLM-without-thinking（无思维链裁判的能力上限，[NeurIPS 2025](https://nips.cc/virtual/2025/loc/san-diego/126590)）。**做法**：把 k2.5-thinking 开关作为一对消融，看裁判角色的推理增益是否值得多花的 token。

**维度 4：能力余量（弱裁判判强输出≈随机）→ 回答"小模型能不能当裁判"。**
依据：On Scalable Oversight with Weak LLMs Judging Strong LLMs（弱裁判对强模型输出接近随机，[NeurIPS 2024](https://proceedings.neurips.cc/paper_files/paper/2024/file/899511e37a8e01e1bd6f6f1d377cc250-Paper-Conference.pdf)）。**做法**：明确红线——便宜档当裁判只允许判"更便宜档当批判者"的组合；强档输出必须由强档裁判判，否则精确率直接崩。

**维度 5：自偏好规避 → 回答"裁判会不会偏袒自家"。
**依据：Self-Preference Bias in LLM-as-a-Judge（[arXiv:2410.21819](https://arxiv.org/abs/2410.21819)）。**做法**：裁判与被评判的批判者尽量跨厂商配对，并留一小批人类标注子集做自偏差量化（Play Favorites 方法，[arXiv:2508.06709](https://arxiv.org/abs/2508.06709)）。

## 4. 对比实验设计（模型×角色矩阵）

**角色**：批判者、裁判两个 LLM 角色（提出者保持规则版，作为零成本对照）。
**实验集**：先 R017 冒烟 8 条 → 全量 390 条 L2（`--max-cases 390`）；后续 L3 gold 出来后再上 60–100 条定案。
**矩阵**：

| 组别 | 批判者 | 裁判 | 体现的差异 |
|---|---|---|---|
| H1–H6 | 每模型同款 | 同款 | 单模型全角色基线（6 组） |
| E1 | glm-4-flash | deepseek-v4-pro | 跨厂商 + 强裁判 |
| E2 | kimi-k2.6 | deepseek-v4-pro | 跨厂商 + 强裁判 |
| E3 | deepseek-v4-flash | glm-4.5 | 跨厂商 + 中档裁判 |
| E4 | glm-4-flash | kimi-k2.5 | 跨厂商 + 旗舰裁判 |
| E5 | deepseek-v4-pro | glm-4-flash | 强批判者 × 便宜裁判（测试维度 4 红线） |
| E6 | kimi-k2.5(thinking) | kimi-k2.5 | 同模型推理模式消融 |

**指标**（每组合）：accepted_precision（对 L2 标签）、unsupported_acceptance_rate、needs_review 率、每用例 in/out token、每用例成本（按冻结价目表折算）、failed_calls、P50/P95 时延。
**决策规则**：先筛 accepted_precision ≥90% 的组合（90% 是硬门槛），再在其中取每用例成本最低者；同时画"成本—精确率"Pareto 图；输掉的组合全量报告，不删。

## 5. 配置流程（一步一步，C 队员手册）

**Step 0 冻结价目表（5 分钟）**：打开三家价格页截图存档，命名 `价格快照_YYYYMMDD_供应商.png`，存 `docs/协作与运维/价格快照/`；把关键价格填进 `config/experiment_models.json`（现多为 null，如实填）。

**Step 1 填 Key（2 分钟）**：复制 `.env.example` 为项目根目录 `.env`，填三行：
```
DEEPSEEK_API_KEY=sk-...
KIMI_API_KEY=sk-...
ZHIPU_API_KEY=你的智谱key
```
`.env` 已被 gitignore，绝不提交、绝不发群。

**Step 2 建环境（5 分钟）**：
```
python -m venv .venv-lab
.venv-lab\Scripts\python.exe -m pip install ".[tracking]"
```

**Step 3 核对注册表（已替你改好）**：`src/yanhai/providers.py` 里三家 models 已对齐在售型号；你只需对照控制台确认模型名没变（变了就在注册表里改一行并告诉我）。

**Step 4 R017 冒烟（第一次真调模型）**：
```
.venv-lab\Scripts\python.exe scripts/run_decision_experiment.py --models "deepseek:deepseek-v4-flash,zhipu:glm-4-flash,kimi:kimi-k2.6" --max-cases 8
```
验收三看：`summary.json` 的 `models_requested` 非空；`stats` 里有 token 数；`skipped` 为空。任一 Key 错/缺都会显式报错或进 skipped，绝不静默。

**Step 5 全量矩阵**：`--max-cases 390`，按第 4 节矩阵逐组合跑（可先同质 6 组，再异质 6 组）；每组一个独立 run 目录，产物六件套。

**Step 6 入库与标签**：
```
.venv-lab\Scripts\python.exe scripts\sync_mlflow.py --run-dir outputs\experiments\<协议>\<时间戳>
```
tags：`owner=C成员`、`data_kind=proxy`、`claim_id=C1-EASG`、`verification_status=passed`。

**Step 7 队员复用 Key**：同一把 Key 四人都能用——各自在本地 `.env` 填同一份即可（Key 不绑定机器）；私聊分发，不进群、不进 git；账单只有一张总单，但每个 run 的 token 数都记录在案，实验级账目可追溯；账户只充小钱，风险封顶余额。

## 6. 降本增效三招（与 B 线联动，写进 R009–R012）

1. **级联判分**：便宜模型先判，仅低置信样本升级强模型（FrugalGPT/SATER，[arXiv:2510.05164](https://aclanthology.org/2025.emnlp-main.531/)）——B 的 R009 校准器输出的置信度就是升级闸门；
2. **结构化 checklist 打分**：把自由文本判分改为分级检查表（RocketEval，[ICLR 2025](https://proceedings.iclr.cc/paper_files/paper/2025/hash/937defc32e8ad2daba66a0e434177ae9-Abstract-Conference.html)），裁判成本可降数量级而不掉精度——对应 B 的 R010 typed issue；
3. **分层裁判**：难度分层，低难子集用便宜裁判（JudgeBoard，[arXiv:2511.15958](https://arxiv.org/abs/2511.15958)）。

## 7. 预算与风险

- Token 估算沿用上轮：390 全矩阵 ≈ 1500–2500 万 tokens ≈ ¥100–200；6 模型矩阵含异质组翻倍余量，¥150 封顶仍在三账户余额内；
- 风险一：模型名/价格变动（DeepSeek 近期有调价新闻）→ 每次运行记录 revision 与价格快照日期；
- 风险二：限流 → 代码自带重试与熔断，失败显式记录 failed_calls（当前 REPORT 不聚合此字段，已列入修复清单）；
- 风险三：自偏好 → 按维度 5 交叉配对并留人类子集校验。
