## 一、我们是谁、在做什么（研究背景）

我们在做**"研海寻踪"**：面向科研文献的知识图谱发现系统，参加挑战杯揭榜挂帅专项赛（XH-202630，发榜单位上海云之脑）。评分：完整性 30 / 创新性 25 / 体验 15 / 实用价值 30。**9 月 5 日交压缩包，9 月 20 日初审，11 月终审**。

**问题是怎么来的**：大模型敢把"A 能治 B"写进知识图谱，却不告诉你出处和条件。我们调研 100+ 篇顶会论文后发现两个事实：第一，图谱里最缺的不是抽取，而是"裁决与更新"**——谁来判关系可信、证据变了怎么办；第二，**"多几个智能体辩论"不是创新**（辩论经常打不过最简单的自一致性投票，评委一问就穿帮）。所以我们的核心主张收敛为一个词：**EASG（证据裁决状态图）**——每条关系带字符级证据、结构化批评、校准风险、不可变事件流；证据新增/删除/反驳/取代时自动重算状态并可重放。

**诚实口径**：查新评级 4.0/10，"候选机制，谨慎推进"；对外禁用"首创/首次/领先"。

## 四、每个方法是怎么来的（idea 来源）

- **为什么状态要用"事件流"而不是"当前值"**：现在的图谱只存"这条关系现在是什么状态"，一旦证据被删、被反驳，系统根本不知道"曾经为什么接受"。事件溯源（event sourcing）的思路：只追加、不覆盖，任何时刻的当前状态都由完整事件流重算——这样"证据变了自动更新"和"随时重放审计"就是同一件事。
- **为什么硬护栏要"模型无关"**：LLM 裁判自己会错（文献里 LLM-as-judge 偏差、辩论失败都有实证）；我们把"没有有效证据就拒绝、绝对化表述要更强证据"写成确定性规则，任何模型都绕不过去。2026 年一篇论文（P102）正好证明了：连"选版本号更大的"这种明说规则，交给 LLM 自由文本判断都会错一半，必须写成显式策略执行——这给了我们直接支撑。
- **为什么批评要"结构化问题类型"而不是一段话**：现在裁判靠关键词在中文句子里找"缺少/绝对化"，像老师只数字数不读内容。把批评改成字段化的问题类型（证据错位/条件不符/来源不独立…），裁判只消费结构化输入，判断才可复算、可消融。
- **为什么校准器要"从数据学"而不是拍脑袋**：0.78/0.58 这两个阈值是当初手调的。校准器（逻辑回归/等距回归）在冻结 dev 上学"分数→真实正确的概率"，顺便输出 ECE/Brier 和 risk-coverage 曲线——评委要的"为什么是 0.78"就有答案了。注意 R006 的教训：**接口分离和确定性执行要拆开测**，别把两者的功劳混在一起。
- **为什么先做 R007/R009 而不是大模型实验**：它们纯 CPU、不花一分钱、不依赖任何人，是推翻 C1 最便宜的反证实验——如果重放不一致或校准器没用，趁早降级止损，这就是"先找能推翻自己的证据"。

## 五、怎么用项目、怎么做你的实验（手把手）

**环境**：Python 3.11+；仓库目录下直接用系统 python 跑测试（实验协议和 MLflow 另用 `.venv-lab`，见 C 的文档）。

**日常三步**：

1. 看裁决逻辑现状：`src/yanhai/agents.py`（规则版三智能体）、`src/yanhai/llm_decision.py`（LLM 版+硬护栏）、`src/yanhai/easg.py`（事件内核，docstring 就是政策说明书）；
2. 跑测试：`python -m unittest discover -s tests`（119 项，应全过；沙箱里会有约 18 项因临时目录报错，属环境问题）；
3. 跑 R006 看 EASG 效果：`python scripts/run_easg_r006.py` → 产物在 `outputs/experiments/easg_r006/<时间戳>/`，六件套齐全，验证章现在是真的。

**做 R007（重放一致性）**：复用 R006 案例集，写 run 脚本对每条案例把事件流重放 3 次、断言投影逐字一致；重放次数**不算独立样本**，只证确定性。产物仍按六件套（run_config/raw_results/summary/cases.csv/REPORT/verification）输出，验证逻辑参考 `scripts/run_easg_r006.py` 的新写法（真比对、失败非零退出）。

**做 R009（校准器）**：输入用冻结 dev 的裁决分数与 gold 标签（A 的 gold 出来前，先用 `data/evaluation/decision_benchmark.json` 的 24 条当 dev）；实现 logistic/isotonic 校准器与固定阈值对比，算 ECE、Brier、risk-coverage 曲线；**test 不能看**。

**提交纪律**：每个实验在开始前先写"研究卡"（测什么/怎么算赢/输了怎么办/预算）；跑完六件套 → 让 C 或 D 复核 → 再决定继续/修改/降级/放弃。
