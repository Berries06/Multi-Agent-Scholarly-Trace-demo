# 研海寻踪 · 成员 B 工作说明

## 这个项目在做什么

"研海寻踪"是我们参加第十九届挑战杯揭榜挂帅专项赛（赛题 XH-202630，发榜单位上海云之脑）的作品：面向科研文献的知识图谱发现系统。评分四块：完整性 30、创新性 25、体验 15、实用价值 30。9 月 5 日交压缩包，9 月 20 日初审，11 月终审。

大模型敢把"A 能治 B"写进知识图谱，却不说出处和条件。我们调研一百多篇论文后发现两件事：第一，图谱里最缺的不是"抽取"，而是"裁决与更新"——谁来判断一条关系可不可信、证据变了图怎么办；第二，"多几个智能体辩论"本身不是创新，辩论在文献里经常打不过最简单的自一致性投票。所以我们的核心主张收敛成一个词：**EASG（证据裁决状态图）**——每条关系带字符级原文证据、结构化批评、校准过的风险分数、一条不可改写的裁决流水账；证据新增、删除、被反驳、被新论文取代时，状态由事件流自动重算，历史可重放、可审计。

口径统一：文献查新评级 4.0/10，对外说"候选机制，谨慎推进"，禁用"首创、首次、领先"。

## 现在走到哪一步了

系统端到端能跑，当前 130 项回归测试通过；规则版三智能体是真实逻辑。最小 EASG 内核 `src/yanhai/easg.py` 已完成第一个实验：12 条手算反事实案例上，事件流方案 12 条全对，而“只存当前值”的静态做法只对 3 条。真模型裁决代码（`llm_decision.py`）带硬护栏与规则回退，实际供应商表现仍需用冻结数据评测。

## 你的工作目标（先看清终点）

比赛级标准一句话：**评委问三句话——"你凭什么接受这条关系？""证据被删了你怎么办？""比单个模型强在哪？"——你要能当场点开任何一条 accepted 关系的完整裁决流水账、现场删一条证据给他看重算、打开消融表说明白每个零件拆掉会损失多少。** 三个回答里有一个靠猜，就要重做。你的全部工作围绕这三个回答展开。

## 你要做的四件事

### 第一件：把裁决协议从玩具版升级为生产版

从 A 手里拿《判题规则》和状态真值表，把规则翻译成代码里的裁决协议。有一个现成的内核 `src/yanhai/easg.py`，文件开头的说明文字就是当前政策，你先读透它，然后做三件事：

1. **事件模型对齐**：每条关系的裁决必须记成不可改写的事件，字段至少包括：事件编号、关系编号、事件类型（新增支持/新增反驳/删除证据/替换跨度/被取代/人工改判）、操作者（哪个智能体还是哪个人）、时间、证据编号、以及当时用的规则版本号。这些字段保证任何时刻的当前状态都能由完整事件流重算，删掉任何一条事件，重放结果立刻不同——这就是"可审计"的技术含义。
2. **批评结构化**：现在批判者写的是一段话，裁判靠关键词在中文句子里猜问题。改成固定字段的问题类型，至少覆盖：证据不存在、证据编号错位、证据跨度没覆盖关系两端、条件不一致、来源不独立、绝对化措辞、单一来源。每个类型配一个代码和严重级别（阻断/警告），裁判只消费这些字段做判断，不再解析自然语言。
3. **硬护栏独立**：无论哪个模型当裁判，以下规则必须由确定性代码强制：没有任何有效证据就拒绝；绝对化表述证据不足就拒绝。这条规则不经过任何模型，任何模型都绕不过去——文献里已有证据表明，连"选版本号更大的"这种明说规则交给大模型自由判断都会错一半，所以护栏必须是代码级的。

做完这些，起草"规则—代码逐条核对表"：每条规则对应哪段代码、哪个单元测试锁住它，交给 A 逐条核对签字。A 签字前不算生效。

### 第二件：把"拍脑袋分数线"换成"校准器"

现在裁判用 0.78/0.58 两个手调的阈值。你要做的事：在验证数据上训练一个简单校准器（逻辑回归或等距回归就够了，不要上复杂模型），把裁判的打分换算成"这条关系真正正确的概率"。产出三样：

1. **ECE 与 Brier 分数**：衡量校准器给出的概率准不准；
2. **风险—覆盖率曲线**：不同阈值下"接受了多少、错收了多少"画成曲线，阈值的选择依据从"拍脑袋"变成"看曲线选点"；
3. **一个诚实的结论**：如果校准器并不比固定阈值强，就照实写"固定阈值够用"——简单方法等效是优点，直接写进作品书当简洁性证据。

注意纪律：校准器只在训练和验证数据上训练，封存数据碰都不许碰，训练过程里每步都要记录，保证评委问"阈值怎么定的"时你能拿出完整决策链。

### 第三件：用消融实验证明每个零件都有用

我们的主张是"这套组合有效"，不是"零件越多越好"。所以逐个拆零件，每个变体在同一批数据上跑一遍，记录精确率掉多少：

- 去掉事件历史（只存当前值）——预期大幅掉分，这是和传统做法的直接对比；
- 去掉结构化批评（退回自然语言一段话）；
- 去掉校准器（退回固定阈值）；
- 去掉硬护栏（看灾难性错误接受涨多少）；
- 大模型裁判换成小模型（看精确率是否崩）。

拆掉某个零件后精确率没变化的，就删掉它，把结论写成"该零件无贡献，已移除"。这比堆砌零件更经得起评委追问。每个变体的运行都留六件套产物（配置、原始结果、汇总、案例表、报告、验证章），验证章现在是真校验：从原始结果重算汇总对得上才签发，对不上直接失败退出。

### 第四件：打通下游，冻结证据契约

关系状态变了，下游必须跟着变：时间线里的技术脉络、研究空白推荐、生成的学习资源，凡是引用了这条关系的，都要反映最新状态，而且能解释"为什么变"。做完这件事后，冻结一份《证据契约》：前端要展示的每条证据长什么样（字段名、类型、从哪里取、什么情况下标什么颜色），写成文档。这份契约是 C 的实验记录和 D 的前端页面的共同标准，谁改都要先过你。

## 你和别人的衔接（逐条说清）

**从 A 拿**：《判题规则》+ 状态真值表（写代码的依据）、训练和验证数据包（带指纹）。没有规则你不动代码；规则和代码核对表由你起草、A 签字。A 的封存数据你一个字节都拿不到，也别要。

**交给 C**：三样东西——结构化批评的字段定义（C 的实验脚本按这些字段收集结果）、校准器和触发策略（哪些情况必须叫强模型来判、哪些可以用便宜模型，这是 C 设计矩阵组合的依据）、指标清单（每组组合必须记录哪些数字）。C 跑完每组实验，把原始结果和失败案例交回给你，由你解释失败切片：哪些是模型能力问题、哪些是代码问题、哪些是数据问题。你的解释写进每组实验的报告，和 C 的数字一起过 D 的复核。

**交给 D**：《证据契约》v1 和一批真实的失败案例。D 的前端按契约渲染证据档案页（字段对不上就找你），D 的审计实验拿你的失败案例当题目。另外 D 是你们三组实验的独立复核人，你的六件套产物交到 D 手里时，要保证从原始结果能重算出汇总——算不出来就是你的产物不合格。

## 做到什么程度才算比赛级

任意一条 accepted 关系，点开能看到从"提出"到"接受"的完整事件链，每环带证据编号和规则版本；删掉一条证据，状态在毫秒级重算且理由可读；消融表里每个零件的贡献都有数字。三个演示里任何一个演不出来，说明协议还没做完。

## 几条要注意的

封存数据不能看，调参数只在训练和验证数据上做；每次实验留齐六件套并让 D 独立复核后才算数；实验失败（校准器没用、某零件无贡献）照实登记，删失败记录是红线；改动对外口径的字段前先和 A、D 对一下，别让三方文档不一致。
