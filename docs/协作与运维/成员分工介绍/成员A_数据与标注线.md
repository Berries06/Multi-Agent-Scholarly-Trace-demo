# 研海寻踪 · 成员 A 工作说明

## 这个项目在做什么

"研海寻踪"是我们参加第十九届挑战杯揭榜挂帅专项赛（赛题 XH-202630，发榜单位上海云之脑）的作品：一个面向科研文献的知识图谱发现系统。评分四块：完整性 30、创新性 25、体验 15、实用价值 30。9 月 5 日交压缩包，9 月 20 日初审，11 月终审。

大模型现在敢把"A 能治 B"这种结论直接写进知识图谱，却不说这句话出自哪篇论文、在什么条件下成立、论文后来有没有被撤回。我们要解决的就是这件事：给图谱里每条关系配一本"证据账本"——三个智能体（一个提议、一个挑刺、一个拍板）裁决一条关系能不能入图；证据一旦新增、删除、被反驳、被新论文取代，状态自动重算，历史可以重放。这套机制叫 EASG（证据裁决状态图）。

有一句口径全队统一：文献查新对这套方案的评级是"谨慎推进的候选机制"（4.0/10），我们不是首创。任何对外材料里都不能出现"首创、首次、领先"这类词，统一说"候选机制，谨慎推进"。

## 现在走到哪一步了

系统已经能从头跑到尾：论文摄入、抽取、三智能体裁决、证据图谱和个性化资源形成闭环，当前 130 项回归测试通过。DeepSeek、Kimi、智谱等提供方已有真实 HTTP 适配；是否具备可用额度以运行时密钥和连接测试为准。B 的裁决协议内核已完成 12 条手算反事实案例验证，文献周报管线也已落地。

但全队有一个命门没解决：**我们手里 390 道测试题全是程序自动造的练习题，没有一道是真人判过的**。评委问"幻觉率多少"，我们现在只能回答"待测"。这件事就是你的工作——你是全队的判卷人。没有你判过的题目，B 和 C 做出的所有实验数字都只是练习成绩，上不了台面。

## 你的工作目标（先看清终点）

比赛级标准一句话：**评委现场问三个硬指标（幻觉率低于 5%、画像与资源难度适配不低于 85%、知识点覆盖率不低于 90%）怎么来的，你能当场打开文件，指出每一道题是谁判的、什么时候判的、两人分歧怎么裁的、数据指纹是什么，分子分母张口就能说清。** 你所有工作都朝这个目标做。

## 你要做的四件事

### 第一件：把"什么样的关系算可信"这套规则定下来

这是全队裁决逻辑的唯一依据，值得花最多心思。做法是：你和 B 各自先想一遍，然后坐在一起逐条对，最终由你落成一份《判题规则》文档，交 B 写代码。规则至少要把下面五个问题回答清楚，每个问题配一个真实例子：

1. **什么算支持证据**：一段原文要满足什么条件才算支持某条关系？只提到两个词算不算？出现在摘要和出现在实验结果里是不是一样的分量？
2. **什么算独立来源**：同一个作者的两篇论文算一个来源还是两个？同一数据集跑出来的两篇报告呢？引用链上下游（A 引 B、B 引 C）算不算独立？定死判定标准，否则"两个独立来源"这句话就没有意义。
3. **什么时候能推翻旧结论**：更晚的论文什么条件下可以把旧关系标成"被取代"？什么情况下只能标成"存在争议"？时间差多少、期刊等级差多少，需要写进规则。
4. **哪些表述必须走人工**：比如"必然""证明""完全消除"这类绝对化措辞，出现就强制拒绝还是强制转人工？把触发词列成清单。
5. **哪些高风险情形必须"待复核"**：单一来源、证据跨句、条件不一致、来源含撤稿记录——列出必须进人工队列的情形。

规则写完的交付形式是两份：一份给人看的《判题规则》（每条规则配判例，判例写"原句是什么、按规则该判什么、为什么"），一份给机器看的"状态真值表"（把每条规则翻译成"输入什么条件、输出什么状态"的表，供 B 直接写进代码）。两份都存进 `docs/协作与运维/` 下并注明版本号。B 写完之后会起草一份"规则—代码逐条核对表"，每条规则对应哪段代码、哪条测试锁住它，逐行列出来交给你签字。**你签字之前，这条规则不算生效**；签字之后，谁改规则都要先经你同意，这是纪律。

### 第二件：组织真人判题，做出标准答案集

判题的对象是"关系级题目"：一道题 = 一条候选关系 + 它的证据原文，判卷人按《判题规则》给出结论（接受 / 拒绝 / 待复核）和一句理由。现成的起点在 `outputs/l3-sample.csv`，里面已经有 28 道分层抽出来的题，每行有题目编号、关系内容、证据，以及留给判卷人填写的"核验结论"列和"备注"列（理由写进备注列）。

流程分四步：

1. **双人盲标**：找两个同学，把《判题规则》发给他们，题目文件一人一份，各自独立判。规矩是判完之前互相不许对答案、不许讨论——单人判卷无法知道"分歧是题目难还是判卷人走神"，两个人独立判，一致的部分才可信。
2. **分歧仲裁**：收回来后逐行对比。两人一致的直接过；不一致的题目单独列一张分歧表，你找第三个人（没参与初始判卷）逐条拍板。同时把两人的一致性算出来（kappa 数值），这个数将来写进作品书——它说明"我们的判卷标准有多清楚"。
3. **扩量**：28 条跑通流程后，扩到 60 到 100 条，覆盖 6 到 10 篇没人标注过的新论文。数量不是越多越好，够算三个硬指标、够分训练和测试两份就停，贪多会拖垮判卷节奏。
4. **打包冻结**：最终版叫"标准答案集"，里面每道题带齐这些字段：论文来源、题目文本、证据原文、判卷人、仲裁人、最终结论、判卷日期、整包数据的 SHA-256 指纹。之后每改一次都要重新算指纹，旧版本不覆盖，防止改了不认账。封存卷的指纹单独登记在 `data/evaluation/` 下的数据清单里（与 390 条练习题的 cases_sha256 登记方式一致），验收时能直接指到文件。

标准答案集要分成三份管理：**训练部分**（给 B 调参数用）、**验证部分**（给 B 和 C 做实验对比用，可以反复用）、**封存部分**（谁也不许提前看，9 月 20 日前后由 C 跑最终主结果时使用一次）。封存部分的关键纪律是"只考一次"——提前泄题或者反复考，成绩就变成背答案，评委能看出来。

### 第三件：写一页"三个硬指标怎么测"

赛题要三个数：幻觉率 <5%、画像—资源难度适配 ≥85%、核心知识点覆盖率 ≥90%。你要写一页《三指标测量协议》，每个指标说清五件事：

1. **定义**：分子分母分别是什么。比如幻觉率建议定义为"被系统接受、但标准答案集判定为不成立的关系数 ÷ 系统接受的关系总数"——具体定义你和 B 对一下，但必须是能算出来的定义；
2. **在哪个数据集上测**：用标准答案集的哪一部分；
3. **失败案例**：当前错了哪几道题、错在哪，要能拿出来给人看，不能只有一个百分比；
4. **置信区间**：样本量小，百分比必须带区间（比如"84.6%（11/13），95% 区间 [57.8%, 95.7%]"这种写法），不带区间的百分比评委直接不信；
5. **口径边界**：说清楚这是"开发小样本上的初步结果"还是"正式实测"——没做完就写没做完，这叫诚实，不叫丢人。

这一页将来原样进作品书第 7 章，D 会拿着它写，写完拿回来找你核对每个数字。

### 第四件：把文献候选卡片的复核跑起来

文献管线会自动扫描 arXiv 新论文（默认每周一批），机器生成四问解读，结果放在 `data/vertical_kb/candidate_queue.json`，每条都标着"待人工复核"。每批新卡片出来时你过一遍：明显误报的标出来剔除，解读与摘要不符的记一笔，确认没问题的签字。签字通过的卡片才能进入下一步（成为正式证据卡的候选）；机器解读永远是阅读辅助，不等于证据。复核的规矩和格式由 D 写一页说明，你按说明执行。

## 你和别人的衔接（逐条说清）

**和 B**：你先把《判题规则》和状态真值表交给 B，B 据此写裁决代码；B 写完把"规则—代码逐条核对表"交回来，你逐条核对、签字生效。之后 B 如果发现规则有歧义或漏洞，来和你讨论修订，修订必须体现在规则文档的新版本里并重新签字。训练和验证数据你交给 B 时只给数据包和指纹，封存数据一个字节都不给。

**和 C**：你给 C 两份东西——训练/验证部分（随便跑）和封存部分（9 月 20 日前后主结果用一次）。C 用完封存卷要在实验配置里登记使用记录，之后你收到登记才算闭环；C 没登记之前你不发第二次。

**和 D**：三指标测量协议交给 D 写作品书；D 写完后拿回来你核对数字和口径。另外你发布的标准答案集、以及 B/C 用你的数据做出的实验数字，都要先过 D 的独立复核，复核通过才算数——这条对全队生效。

## 做到什么程度才算比赛级

评委问三个数怎么来的，你打开标准答案集能指到每一道题：谁判的、哪一天、分歧怎么裁的、指纹是多少；三个指标的分子分母、失败案例、置信区间张口就清；任何场合都能说清哪些数据是人工标注、哪些是程序生成。到不了这个程度，B 和 C 的实验做得再漂亮，最后的分数也站不住——因为分数的分母是你给的。

## 几条要注意的

练习题在任何场合都不能冒充考试成绩；判卷过程中两人不许互相抄答案；标准答案集每改一次重算指纹、旧版不覆盖；封存卷泄题等于全队白干，这条没有例外。
