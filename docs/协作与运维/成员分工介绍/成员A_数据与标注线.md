# 研海寻踪 · 成员 A 工作说明

## 这个项目在做什么

"研海寻踪"是我们参加挑战杯揭榜挂帅专项赛（赛题 XH-202630，发榜单位上海云之脑）的作品：一个面向科研文献的知识图谱系统。大模型现在敢把"A 能治 B"直接写进图谱，却不说这句话出自哪篇论文、在什么条件下成立、论文后来有没有被撤回。我们要解决的就是这件事：给图谱里每条关系配一本"证据账本"——三个智能体（一个提议、一个挑刺、一个拍板）裁决关系能不能入图，证据一旦新增、删除、被反驳或被新论文取代，状态自动重算。

对外口径要记住：这套方案在文献查新里是"谨慎推进的候选机制"，不是首创。任何材料里都不能出现"首创、首次、领先"这类词。

## 现在走到哪一步了

系统已经能从头跑到尾，128 项测试全部通过，三家真模型（DeepSeek、Kimi、智谱）已经选定并买好额度，实验平台也搭好了。但全队有个命门没解决：**我们手里 390 道测试题全是程序自动造的练习题，没有一道是真人判过的**。评委问"幻觉率多少"，我们现在只能回答"待测"。这件事就是你的工作——你是全队的判卷人，没有你判过的题目，所有人做的实验都拿不出真成绩。

## 你要做什么

一句话：**制定判题规则，组织真人把题判出来，写清楚三个硬指标怎么测。**

具体三件事：

**第一件，把"什么样的关系算可信"这套规则定下来。** 这件事和 B 一起做，不是各写各的：你们先各自想一遍，然后坐在一起逐条对——哪句话算支持、哪篇论文算独立来源（同一个作者、同一批数据算不算两篇独立证据）、什么情况下后来论文可以推翻旧结论、什么情况下只能存疑、哪些表述（比如"必然""证明"）必须走人工。对完之后由你把这些结论落成一份《判题规则》，里面每个规则配一个实际例子，B 拿着这份规则去写代码，写完再拿回来和你逐条核对一遍代码是不是真的实现了规则。你们核对确认后的最终版，就是全队以后所有裁决逻辑的唯一依据，谁都不许单方面改。

**第二件，组织真人判题。** 现在有一份现成的 28 道抽查题在 `outputs/l3-sample.csv`。找两个同学，把规则发给他们，让他们各自独立判一遍（判完之前互相不要对答案）；两人意见不一样的题收集起来，你找第三人拍板。这一步跑通后，把题量扩到 60 到 100 道，覆盖 6 到 10 篇没人标注过的新论文。判完的结果打包成"标准答案集"：每道题记清楚论文来源、判卷人、仲裁人、最终答案和哈希值，练习题部分可以给 B 和 C 公开用，但留出一批只封存、谁都不能提前看——那是给 C 最终考试用的卷子，只能用一次。

**第三件，写一页"三个硬指标怎么测"。** 赛题要三个数：幻觉率低于 5%、画像与资源难度适配不低于 85%、知识点覆盖率不低于 90%。你要把每个数写清楚：分子是什么、分母是什么、在哪个数据集上测、错了哪几道题、置信区间怎么算。这一页将来直接进作品书，D 会来问你要。

另外有一件每周的小事：文献管线现在每周自动扫出新论文、生成候选卡片放在 `data/vertical_kb/candidate_queue.json`，这些卡片都是机器初筛的，需要你每周过一遍、把明显不对的标出来，确认没问题的签字升级。

## 你和别人的衔接

- **和 B**：你先给规则，B 写代码；B 写完代码把"规则—代码逐条核对表"交回来，你签字确认才算生效。
- **给 C**：你打包好的标准答案集分两份交出去——练习部分 C 可以随便跑实验用；封存的考试卷只在 9 月 20 日前后由 C 跑最终主结果时用一次，C 跑完要在实验记录里登记"已使用"，你不能提前给，给了就没意义。
- **给 D**：三指标测量协议交给 D，D 写进作品书评测章；D 会拿写好的文字回来找你核对数字和口径。

## 做到什么程度才算比赛级

评委现场会问三个数怎么来的。你的工作做完的标志是：能当场打开标准答案集的文件，指出每一道题是谁判的、什么时候判的、两人分歧怎么裁的、哈希是什么；三个硬指标的分子分母张口就能说清。到不了这个程度，B 和 C 的实验数字再漂亮也站不住。

## 几条要注意的

练习题不能冒充考试成绩，任何场合都要说清数据是"人工标注"还是"程序生成"；判卷过程中两人不许互相抄答案；标准答案集每改一次都要重新算哈希，旧版本不许覆盖。
