# 研海寻踪 · 成员 A 工作说明

> 版本：2026-08-24 修订版
>
> 定位：数据协议、人工标注与金标准发布负责人

## 这个项目在做什么

“研海寻踪”是第十九届挑战杯揭榜挂帅专项赛赛题 XH-202630 的参赛项目。系统从科研论文中抽取关系，并通过提出者、批判者和裁判形成可审计的证据裁决记录；证据被新增、删除、反驳或取代时，关系状态能够重算和重放。这套候选机制称为 EASG（证据裁决状态图）。

全队统一口径：当前新颖性审查为“候选机制，谨慎推进”（4.0/10）。在正式查新和实验完成前，不使用“首创、首次、领先、零幻觉”等表述。

## 你在全队中的位置

你不是“替全队把所有题都判一遍的人”，而是**金标准流程的负责人和发布人**。你的核心责任是保证：规则清楚、标注者相互独立、争议有仲裁、数据可追溯、测试集没有泄露。

正式责任边界如下：

- 你负责科学语义、标注指南、人员组织、版本和发布；
- 两名独立标注者负责初始盲标；
- 第三名具备相应背景的成员负责分歧仲裁；
- 你不能同时兼任“初始标注者”和“同一批数据的最终仲裁者”；
- B 负责把你的规则翻译为机器 schema 和代码测试；
- C 负责盲标包生成、校验、哈希和存储工具，但不得看到封存答案；
- D 负责检查流程、文件和数字能否复算，不代替领域仲裁。

## 当前最重要的事实

现有 390 条案例都是程序构造的 synthetic proxy，只能证明工程行为，不能形成正式性能结论。

`outputs/l3-sample.csv` 的 28 条样本也不能直接作为盲标包：它包含自动标签和 `positive/no_evidence/overclaim` 等构造类型，却没有论文原文、上下文和精确证据跨度。该文件从现在起统一标记为：

> **标注训练与流程调试集，不是 gold，不计算正式性能。**

在 C 生成合格的盲标包、D 完成泄露检查之前，不组织正式初标。

## 第一件事：与 B 冻结《标注指南 v1》

你和 B 共同完成规则会签，但分工不同：你决定科学含义，B 决定机器如何表达。指南至少回答下列问题，并为每项提供正例、反例和边界例：

1. 支持、反驳、相关但不足、无关分别是什么；
2. “证据立场”和“是否允许入图”如何分开；
3. `contested`、`superseded`、`retracted-risk` 和普通条件差异如何区分；
4. 同作者、同机构、同数据集、共同基金和引用上下游是否属于独立来源；
5. 摘要、方法、结果、讨论、综述转述分别能支持多强的关系；
6. 哪些绝对化措辞、跨句证据、单一来源和版本异常必须进入 `needs_review`；
7. 撤稿、勘误、关注声明、恢复和新版本如何影响关系风险，且为什么不能自动等同于“所有结论错误”。

指南必须同时定义两层标签：

```text
evidence_stance:
  SUPPORTS / REFUTES / RELATED_INSUFFICIENT / IRRELEVANT

admission_decision:
  ACCEPT / REJECT / NEEDS_REVIEW
```

同时确定 `issue_codes`、来源独立性风险、条件、时间、模态词和证据充分性字段。交付物是《标注指南 v1》和《状态真值表 v1》，由 A、B 会签；以后任何变更都新增版本，不覆盖旧版。

## 第二件事：冻结真实盲标包规范

你向 C 提交字段需求，C 负责生成工具。发给两名标注者的文件至少包含：

```text
case_id、paper_id、标题、年份、DOI/官方链接、论文版本
source、relation、target
证据原文、前后文、章节/页码、字符起止位置
适用对象、条件、时间和模态词
待填写的 evidence_stance、admission_decision、issue_codes、理由和置信度
```

以下内容只能进入隐藏答案或构造记录，严禁出现在盲标表：

```text
自动标签、构造类型、系统预测、另一名标注者答案、最终仲裁答案
```

你负责确认字段足以完成科学判断；D 负责检查是否仍有标签泄露；两项都通过后才能发给标注者。

## 第三件事：组织真实论文金标准

流程分三层，不能跳级：

1. **规则训练**：使用现有 28 条程序题中的 6–10 条共同讨论，只用于发现指南歧义；
2. **真实 pilot**：从 2–3 篇未见开放论文中生成 20–30 条真实关系，两名标注者独立标注、第三人仲裁，用于验证流程和估计工作量；
3. **正式扩量**：扩展到 6–10 篇未见论文、60–100 条以上关系。按论文切分 train/dev/test，不能把同一论文的关系拆到不同分区。

自然分布集和人为压力集必须分别管理：

- 自然分布集用于报告现实 coverage 和 accepted risk；
- 平衡压力集用于比较特定错误类型；
- 不得把平衡压力集上的比例冒充现实发生率。

正式数据包至少保存论文来源、证据原文、标注者、仲裁者、日期、规则版本、许可状态、数据版本和 SHA-256。原始层只读，清洗和修订产生新版本。

## 第四件事：制定三个指标的测量协议

你负责冻结分子、分母、数据分区和置信区间；B 负责提供可计算字段，C 负责运行，D 负责复算。

至少同时报告：

- accepted precision / unsupported acceptance rate；
- coverage / gold recall；
- 画像—资源难度适配率；
- 核心知识点覆盖率；
- 分子、分母、95% 区间和失败案例。

“幻觉率低于 5%”不能只看点估计。若采用双侧 95% Wilson 区间，即使 0 次错误，也至少需要 73 条被系统接受的独立样本，区间上界才低于 5%。若样本不足，统一写“pilot 点估计，尚不能证明达到门槛”。

## 第五件事：管理文献和候选卡片

论文检索与数据入口使用同目录下的《成员 A · 论文与数据检索关键词清单》。你的重点是为真实 gold 找到未见、开放、可标注的论文，不承担全队全部 novelty 检索；最近工作差分和专利检索由 D 牵头。

`data/vertical_kb/candidate_queue.json` 中的机器四问解读永远只是阅读辅助。你只负责核对来源、摘要一致性和能否升级为 evidence-card 候选；不得把机器解读直接写成证据或 gold。

## 你和其他成员的接口

**给 B**：标注指南、状态真值表、train/dev 数据版本和哈希。B 可以在指南冻结前并行开发 schema 骨架，但正式语义测试必须由你签字。

**给 C**：盲标包字段规范和可公开的 train/dev。封存 test 由你保管；C 只有在配置、模型、阈值和预算全部冻结后才能申请一次性使用。

**给 D**：数据卡、三指标测量协议、分歧记录和可公开的失败案例。D 检查流程与数字，不替代领域判断。

## 当前执行顺序

1. 与 B 完成标注指南和状态真值表；
2. 向 C 提交盲标包字段规范；
3. 让 D 检查盲化和许可记录；
4. 用 6–10 条旧题做标注训练；
5. 用 2–3 篇未见论文完成 20–30 条真实 pilot；
6. 再决定是否扩到 60–100 条以及正式指标所需样本量；
7. train/dev 发布后，封存 test 继续由你保管。

## 红线

- 程序标签不能冒充人工 gold；
- 自动构造类型不能出现在盲标表；
- 同一个人不能既做初标又对自己的分歧做最终仲裁；
- 标注分歧不能私下“对答案”消失；
- 测试集不能按行随机切分，必须按论文切分；
- 数据每次修改都生成新版本和新哈希；
- 样本不足时不能宣称达到比赛硬指标。
