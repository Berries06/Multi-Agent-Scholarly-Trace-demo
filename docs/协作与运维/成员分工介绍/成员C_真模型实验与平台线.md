# 研海寻踪 · 成员 C 工作说明

## 这个项目在做什么

"研海寻踪"是我们参加第十九届挑战杯揭榜挂帅专项赛（赛题 XH-202630，发榜单位上海云之脑）的作品：面向科研文献的知识图谱发现系统。评分四块：完整性 30、创新性 25、体验 15、实用价值 30。9 月 5 日交压缩包，9 月 20 日初审，11 月终审。

核心机制叫 EASG（证据裁决状态图）：三个智能体——提出者、批判者、裁判——裁决一条关系能不能进图谱，证据变了自动更新。评委对"三个智能体"这个说法一定会追问三句："你真调了模型吗？""比单个模型强在哪？""成本划不划算？"**这三个问题的答案都在你这条线上**，全队只有你能提供真模型证据。

口径统一：文献查新评级 4.0/10，对外说"候选机制，谨慎推进"，禁用"首创、领先"。

## 现在走到哪一步了

系统端到端能跑，128 项测试全过。真模型代码全部就绪：DeepSeek、Kimi、智谱三家的接口是真实 HTTP 实现，LLM 版批判者和裁判带硬护栏与规则回退，实验脚本保证"缺 Key 就显式跳过，绝不偷偷用规则冒充模型"。三家模型目录和价格已经定稿入档（`config/experiment_models.json`，2026-08-24 快照），Key 已经买好，只差填进 `.env` 文件。实验记录平台 MLflow 配好，390 道冻结测试题备好，文献周报管线也已落地——万事俱备，就差你的第一批真模型数字。

## 你的工作目标（先看清终点）

比赛级标准一句话：**评委问"比单模型强在哪"，你能打开风险—成本散点图指给他看——同样精确率下哪组组合花最少钱，数字背后是哪个 run 目录、哪次验证；评委问成本，你能报出每组实验真实消耗的 token 和钱。** 到不了这个程度，真模型实验等于没做，作品里"多智能体"三个字就一直是口头说法。

## 你要做的三件事

### 第一件：把 Key 和实验环境接好

1. **填 Key**：三家的 Key 填进项目根目录的 `.env` 文件，三行分别是 `DEEPSEEK_API_KEY`、`KIMI_API_KEY`、`ZHIPU_API_KEY`（等号后直接贴 Key，不加引号不留空格）。这个文件不进 git、不发群、不发聊天记录——它被 `.gitignore` 忽略了，仓库里只有 `.env.example` 模板。填完跑一条验证命令确认三个变量都能读到（只检查读没读到，不打印 Key 内容）。
2. **建实验环境**：`python -m venv .venv-lab`，然后 `.venv-lab\Scripts\python.exe -m pip install ".[tracking]"`。实验和 MLflow 全部用这个环境跑，产品界面用系统 Python，两套解释器分开是现状，别混。
3. **价格表维护**：价格已入档 `config/experiment_models.json`（快照日期 2026-08-24，货币分列）。控制台调价时你去更新这个文件并改快照日期；成本数字一律以这份文件为准，价格查不到就留空，不许编。

### 第二件：先冒烟，再跑全量矩阵

**冒烟（第一次真调模型）**，命令：

```
.venv-lab\Scripts\python.exe scripts\run_decision_experiment.py --models "deepseek:deepseek-v4-flash,zhipu:glm-4-flash,kimi:kimi-k2.6" --max-cases 8
```

跑完看结果文件里的三个验收点，三条全过才算通：`models_requested` 列表非空（三家都真的申请了）；`stats` 里有 token 计数（真的调用了）；`skipped` 为空（没有组合被静默跳过）。任何一家 Key 填错或缺，这里都会显式报错或进 skipped，绝不会假装成功——这是设计，不是故障。

**全量矩阵（12 组）**，`--max-cases 390` 按下面跑。前半是批判者、后半是裁判：

- 六个同质组：每个模型自己当批判者又当裁判（deepseek-v4-flash、deepseek-v4-pro、kimi-k2.6、kimi-k3、glm-4-flash、glm-5-turbo）——这是"单模型全角色"基线；
- 六个异质组：glm-4-flash×deepseek-v4-pro、kimi-k2.6×deepseek-v4-pro、deepseek-v4-flash×glm-5-turbo、glm-4-flash×kimi-k3、deepseek-v4-pro×glm-4-flash、kimi-k2.6×kimi-k3——分别测免费批判者配强裁判、Agent 专用裁判、推理旗舰裁判、以及强批判者配免费裁判（看便宜裁判会不会崩）。

每组记录：精确率（对练习题标签）、错误接收率、待复核率、每道题的输入输出 token、折算成本、耗时、失败调用数。每组一个独立 run 目录，六件套产物齐全。矩阵的意义是回答三个问题：哪个模型够 90% 精确率（硬门槛）、同样精确率下谁最便宜（成本阶梯）、跨厂商搭配是否比同质更稳（异质性主张）。

### 第三件：画曲线、做冻结、入库

1. 把所有组合画成"成本—精确率"散点图；先圈出精确率过 90% 的组合，再在其中挑成本最低的，这就是推荐配置；
2. 输掉的组合全量保留、全部入库——只报好看的组是红线，评委问"别的组合呢"你要有全部数据；
3. 每组同步进 MLflow：`.venv-lab\Scripts\python.exe scripts\sync_mlflow.py --run-dir outputs\experiments\<协议>\<时间戳>`，打上标签（负责人、数据性质 proxy、主张编号 C1-EASG）；
4. 9 月 20 日前后，用 A 的封存考试卷跑最终主结果——**只跑一次**，跑完在实验配置里登记使用记录并告知 A。

另外一件持续的小事：文献周报管线（`scripts/weekly_literature_scan.py`）会定期扫描新论文（默认每周一批）；Key 填好后加 `--interpret` 参数让便宜模型自动生成四问解读，产出周报和候选卡片给 A 复核。缺 Key 时该参数会显式报错退出，这是有意为之。

## 你和别人的衔接（逐条说清）

**从 B 拿**：结构化批评字段、校准器、触发策略、指标清单。你跑矩阵时严格按这些记录，跑完每组把原始结果和失败案例打包交给 B，由 B 分析失败切片（模型问题还是代码问题），B 的解释写进每组报告，和你的数字一起交 D 复核。

**从 A 拿**：训练/验证数据（随便跑）和封存考试卷（主结果用一次）。用封存卷之前和 A 确认，用完登记；登记之前 A 不会发第二次。

**交给 D**：录视频和写作品书要用的"真模型片段"和矩阵数字。你只交出带验证章的 run 目录路径，D 直接引用目录里的产物，不复制数字过去；任何一次性调参秀都不许流向视频——数字和实验严格一致是底线。

## 做到什么程度才算比赛级

Pareto 图上的每个点能点开对应的 run 目录和验证章；每一组实验的真实 token 消耗和成本有账可查；封存卷的使用记录完整。三样齐了，评委的三问就有答案。

## 几条要注意的

缺 Key 就记"跳过"，绝不允许拿规则模型冒充；成本只认入档价格表；每组实验跑完交 D 独立复核，复核通过的数字才允许进作品书和视频；模型名以控制台在售为准，控制台变了型号就去 `providers.py` 注册表里改并通知全队。
