# 测试案例集扩充指南

> 目标：把决策对比实验从"24 条冻结压力命题"扩到**任意规模、任意来源的案例集**，
> 最终以"双人标注真实金标准"替代合成初筛池。

## 1. 案例集 JSON 格式

```json
{
  "benchmark_id": "real-annotated-v1",
  "domain": "scientific-ie-kg",
  "frozen_on": "2026-08-25",
  "scope": "真实论文标注集：来自开发集之外的 3 篇全文，双人标注+仲裁",
  "cases": [
    {
      "claim_id": "R-001",
      "source": "multi-agent debate",
      "relation": "improves",
      "target": "factuality",
      "relation_type": "IMPROVES",
      "base_confidence": 0.86,
      "evidence_ids": ["evidence:..."],
      "gold_supported": true,
      "error_type": null,
      "annotators": ["成员A", "成员B"],
      "note": "证据跨度覆盖两端，语义一致"
    }
  ]
}
```

**必填字段**（实验脚本会校验）：`claim_id`、`source`、`relation`、`target`、
`relation_type`、`base_confidence`、`evidence_ids`（数组）、`gold_supported`（布尔）。

**建议字段**：`error_type`（正确案例写 null；错误案例标
`no_evidence / wrong_span / type_mismatch / overclaim / cooccurrence / other`）、
`annotators`、`note`（仲裁记录）。

## 2. 怎么跑自定义案例集

```powershell
$env:PYTHONPATH="src"
python scripts/run_decision_experiment.py --cases data/evaluation/real-annotated-v1.json --models "deepseek:deepseek-chat,zhipu:glm-4-flash"
```

不传 `--cases` 时默认用 24 条冻结压力命题（快速初筛用）。

## 3. 真实案例从哪来（对应差距 4：金标准）

1. 从**开发集之外**的论文全文抽候选（用 `scripts/实验台/端到端流水线实验台.py` 或产品论文摄入）；
2. 两名成员**独立标注** `gold_supported` 与 `error_type`，不同意见交第三人仲裁；
3. 记录标注者与理由（上面的 annotators/note 字段），计算一致率（Krippendorff's α / Cohen's κ）；
4. 案例集**冻结**后不再改动；后续模型/机制迭代一律不触碰该文件；
5. 用同一案例集跑全部对比组合，结论才有资格进入作品书。

## 4. 纪律

- 合成初筛池（24 条）与真实金标准集**分开存放、分开报告**，结论措辞分开；
- 冻结测试集不删除不利案例、不按系统表现改标签；
- 扩容规模建议：初筛 24 条 → 真实集 ≥60 条关系/证据跨度（对应 `创新机制与实验.md` 的 Track B 门槛）。
