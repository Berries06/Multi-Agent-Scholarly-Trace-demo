## 四、每个方法是怎么来的（idea 来源）

- **为什么要"模型×角色"矩阵而不是"一个模型跑到底"**：三个智能体可以用不同模型（比如便宜模型当提出者、强模型当裁判）。文献里"辩论经常不敌自一致性"的一个重要原因是同模型三个角色共享同样的盲区；**异质组合**（不同模型、独立检索、确定性护栏）才是文献认可的方向（SELENE、iMAD 都在做选择性/异质辩论）。矩阵就是把这些组合系统地测一遍。
- **为什么要"风险—成本 Pareto"**：评委问"多智能体比单模型贵，凭什么是创新？"我们的答案必须是数据：**在相同覆盖率下，哪种组合用最少的钱减少最多的错误接受**。如果纯规则或单模型就是最优，那就大方承认、删掉多余的 Agent——这叫"简洁性结论"，是加分项不是丢分项。
- **为什么要冻结价格快照**：API 价格会变、模型会更新。不冻结价格，"成本对比"就说不清是哪天的账；不记录模型版本，"模型漂移"会让实验结果无法复现。所以实验前先冻结"价格表 + 模型清单 + 预算上限"。
- **为什么缺 Key 必须 skipped 而不是静默回退**：如果允许偷偷回退，人读报告会以为"模型 A 表现不错"，实际全是规则跑的——这就是"AI 欺骗"，答辩被戳穿是致命的。我们的纪律是：失败要能被看见。
- **为什么要 MLflow**：它只是"实验记录本和对比台"——参数、指标、产物、验证收据集中管理，谁跑的都查得到。注意口径：**MLflow 里的记录不等于科学结论**，只有带验证收据、过了预设门槛的才能进作品书。

## 五、怎么用项目、怎么做你的实验（手把手）

**环境（一次性，10 分钟）**：
1. Python 3.11+；
2. `git clone` 仓库；
3. 建实验专用环境（当前文档缺这一步，务必执行）：
   ```
   python -m venv .venv-lab
   .venv-lab\Scripts\python.exe -m pip install ".[tracking]"
   ```
4. Key 只填进项目根目录 `.env`（格式见 `src/yanhai/providers.py` 的 `load_config_from_env` 或群里问我要模板）。

**日常三条命令**：
- 启动实验记录本：`RUN_MLFLOW.bat` → `http://127.0.0.1:5000/`；停止 `STOP_MLFLOW.bat`；
- 跑六套公开实验协议：`RUN_PUBLIC_EXPERIMENTS.bat`（验证通过后自动同步 MLflow）；
- 单目录同步：`.venv-lab\Scripts\python.exe scripts\sync_mlflow.py --run-dir outputs\experiments\<协议>\<时间戳>`。

**你的实验流程（按序）**：
1. **R017 冒烟**：`.venv-lab\Scripts\python.exe scripts/run_decision_experiment.py --models "deepseek:deepseek-chat,zhipu:glm-4-flash" --max-cases 8` → 检查 summary.json 里 `models_requested` 非空、`stats` 有 token 数、缺 Key 的组合在 `skipped`；
2. **R001–R003 标准化**：把 `scripts/run_decision_experiment.py` 迁进 `tests/experiments/07_decision_model_matrix/`（复用 `framework.py` 的六件套与验证逻辑）；写一个"故意损坏产物必须非零退出"的负测试（R002）；
3. **全量矩阵**：`--max-cases 390` 跑"模型×角色"组合，产出成本/风险/时延表；
4. **Pareto**（R020）：横轴成本、纵轴风险，标出前沿组合；用 `sync_mlflow.py` 入库，加 tags（`owner=你`, `data_kind=proxy`, `claim_id=C1-EASG`）；
5. **M4 主结果**（9-20 前，用 A 的 test）：只跑一次，跑完找 B 或 D 独立复核再下结论。
