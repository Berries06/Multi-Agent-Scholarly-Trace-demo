## 5. 标准更新流程

### Web 版

1. 运行全部自动化测试；
2. 运行 `scripts/build_web_release.ps1`；
3. 上传 TGZ 到新的 `/opt/yanhai-agent-demo/releases/<version>/`；
4. 检查属主和只读资源；
5. 切换 `current` 软链接；
6. 重启 `yanhai-agent-demo`；
7. 检查健康端点和 systemd 日志；
8. 异常时把软链接切回上一版本。

### PyQt 桌面端

1. 更新版本号和发行说明；
2. 运行 `scripts/构建桌面应用.ps1`；
3. 在 Windows 10/11 x64 上执行冻结版启动测试；
4. 计算 ZIP 大小与 SHA-256；
5. 同步 ZIP 到下载目录；
6. 同步更新下载页中的文件名、大小和 SHA-256；
7. 保留上一版本，直到新版本由人工验收。

### 页面或 Nginx

1. 备份现有文件；
2. 仅修改 AgentDemo 所需位置；
3. Nginx 修改后必须先运行 `nginx -t`；
4. 使用 `systemctl reload nginx` 热加载，不直接中断主站；
5. 同时检查个人主页和 AgentDemo，防止路由覆盖。

当前拓扑、环境和回滚边界以 [`部署说明.md`](部署说明.md) 为准；旧版部署方案仅保存在 `docs/归档/部署/` 中供追溯。

## 6. 安全边界

- 用户 API Key 只随单次 HTTPS 请求进入服务进程内存；
- 不使用 Cookie、`localStorage`、`sessionStorage`、日志或文件保存 Key；
- Nginx access log 不记录请求体；
- 只提供账号登录，不提供公开注册；账号由服务器管理员通过 `scripts/后台创建用户.py` 创建。会话 Cookie 标记为 HttpOnly + SameSite=Lax，登录用户的学习画像按 user_id 隔离存取；
- 免费 DeepSeek Flash 由服务端代管 Key（读取 `secret/DeepSeekAPI.txt`），Key 只存于服务端内存，不下发到前端，也不进入日志；其余供应商仍由用户自备 Key；
- 用户密码使用 scrypt 加盐哈希存储，不存明文；生产库需做好备份与访问控制；
- 线上真实模型调用可能产生供应商费用，验收应使用低额度测试 Key。

## 8. 是否需要公网域名

不必须。把 ZIP 交给评委本地运行时，`127.0.0.1` 更可靠，也不会把服务暴露给互联网。公网地址适合远程评审和宣传页，但要区分两种情况：

### 临时、有人值守的演示

在只含合成画像和公开论文元数据的机器上，可安装 `cloudflared` 后运行：

```powershell
cloudflared tunnel --url http://127.0.0.1:8766
```

它会返回随机 `trycloudflare.com` 地址。Cloudflare 官方明确把 Quick Tunnel 定位为测试/开发用途，存在并发与功能限制，因此不应把它写进长期交付承诺。演示结束立即停止进程，不上传私有论文、API Token 或真实学习者信息。

### 固定域名、长期可访问

使用命名隧道或云主机，在 HTTPS 反向代理或零信任访问控制之后运行容器；不要直接把 8766 端口裸露到公网。Caddy、Nginx 或 Cloudflare Access 均可承担 TLS、认证、限流和审计。

当前单进程 Demo 不是多租户生产系统。公网长期部署前还需补齐集中式状态、用户认证、持久任务队列、监控告警、备份与隐私审查。
