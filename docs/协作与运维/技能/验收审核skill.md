# 验收审核 skill（验收员操作手册 B）

> 改编自 wentorai/research-plugins 的 [peer-review-guide](https://github.com/wentorai/research-plugins/blob/main/skills/research/paper-review/peer-review-guide/SKILL.md) 三遍审读框架，并针对"任务完成度验收"定制。
> 用途：主代理每完成一个任务，验收员用本 skill 对交付做独立验收。只读 + 跑测试命令，不修改任何文件。

## 三遍审读

**第一遍（总览对照）**：把任务原文要求逐句拆成可检查条目（编号列表）；扫读交付物结构，标出"哪条要求对应哪份文件哪一节"。缺映射的条目直接进 FAIL 候选。

**第二遍（逐条深度核验）**：
- 每条要求：读对应文件的**全部相关内容**（不是看标题），检查落实深度；
- 每个数字/声明：回溯源文件（实验产物、配置、git log、测试输出）；
- 每条命令/路径：能跑就跑（测试命令必须实际执行并记录输出）；
- 每处交接：检查接收方文档里是否也有对应表述（单向承诺不算交接）。

**第三遍（打分与建议）**：按五维打分（1–5），产出总判定与修复清单。

## 评估维度与权重

| 维度 | 权重 | 核心问题 |
|---|---|---|
| 要求覆盖度 | 0.30 | 任务原文每条要求是否都被落实，而不是被忽略或偷换 |
| 细节深度 | 0.30 | 是否达到"越详细越好"：有命令、有文件路径、有验收标准、有失败处理；"提了一句"不得分 |
| 事实准确性 | 0.20 | 数字与仓库一致；交付声明（已完成/已提交/已同步）有 git 或文件证据 |
| 文笔与无 AI 痕迹 | 0.10 | 自然语言、无模板词、无空话 |
| 可执行性 | 0.10 | 一个不了解项目的新成员读完能否直接开工 |

## 判定规则（硬性）

1. 任何维度 ≤2 分 → 总判定 FAIL；
2. 覆盖度或深度任一 <3 分 → 总判定 PARTIAL 起，不得 PASS；
3. 主代理的声明被证伪（如"已提交"实际未提交）→ 直接 FAIL，并在报告中单列"声明失实"；
4. PASS 必须同时满足：全部要求有深度落实、所有数字可回溯、无声明失实、文笔无模板痕迹。

## 输出格式

```
总判定: PASS / FAIL / PARTIAL
条目核验表: 任务要求条目 | 对应文件 | 落实深度(1-5) | 证据(文件:行号/命令输出)
五维打分: 每维分数+理由
声明核验: 主代理声明 | 证据 | 相符/失实
修复清单: 按优先级排序，每条给具体改法
```
报告存到 `docs/变更记录/`，文件名使用 `验收_<日期>_<对象>.md`，不改被验收文件。
