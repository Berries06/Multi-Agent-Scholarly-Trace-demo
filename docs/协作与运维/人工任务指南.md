# 研海寻踪：项目伙伴行动指南

> 给项目组同学看的版本。预计阅读时间：5 分钟。

## 先说人话：我们在做什么

我们想做一个能“读很多论文、找出论文之间关系”的科研助手。

普通搜索只能给出一串论文。我们希望它还能回答：

- 这个结论来自哪篇论文？
- 不同论文有没有互相矛盾？
- 一个技术是怎么发展过来的？
- 哪些方向可能还没人认真研究？
- 面对不同基础的人，应该先看什么、练什么？

系统固定为三个分工不同的 Agent：

1. **学情诊断与学习规划 Agent**：理解用户基础、目标和反馈；
2. **证据检索与知识图谱 Agent**：检索论文并在内部完成命题生成、批判和反证；
3. **个性化教学与反馈 Agent**：生成导读、实操、测评并收集问卷。

另有一个非 Agent 的质量评估与准入模块，决定哪些知识可以进入教学资源。

这就是“研海寻踪”。

## 我们现在做到哪了

好消息：

- 网页 Demo 已经能运行；
- 可以选择不同学习者；
- 可以展示多个 AI 的工作流程；
- 可以生成导读、实操指南和测验；
- 可以显示论文与结论的关系图。
- 可以展示句级证据、反证过程、明确拒答和研究空白候选；
- 已有 6 组自动实验，会保存原始数据、表格和简报。

目前最缺的不是页面，而是**可信的数据和实验**：

- 论文数量还少；
- 有些内容还是固定模板；
- AI 是否真的降低幻觉，还没有独立测试证明；
- 现在的漂亮分数只是程序回归结果，不能直接当比赛成绩；
- 我们需要用真实论文、标准测试集和人工复核来证明效果。

接下来大家主要帮助完成三件事：

> 找论文、做可靠测试题、检查 AI 的答案。

不要求每个人都会写代码。

如果你只负责运行实验：在项目根目录执行
`python -m tests.experiments.run_all`，然后把新生成的
`outputs/experiments/` 目录交给负责人。不要删掉“不好看”的结果，也不要把
mock 分数写成比赛正式成绩。

## 你可以选择哪种任务

每个人选一种最适合自己的即可。

### 任务 A：找论文

适合：喜欢搜索资料、不怕看英文标题的同学。

你需要做：

1. 按负责人给的关键词找论文；
2. 优先找 arXiv、ACL Anthology、期刊官网等可靠来源；
3. 记录标题、年份、链接和它为什么有用；
4. 检查论文是否真的存在，不要只抄 AI 给出的题目。

每篇论文提交：

```text
论文标题：
年份：
论文链接：
它和项目哪个部分有关：
我是否打开原网页核对过：是 / 否
备注：
```

一次任务建议找 5-10 篇，不追求一次找几百篇。

### 任务 B：核对论文结论

适合：愿意仔细读摘要和结论的同学。

你需要做：

1. 阅读论文摘要、实验结果和结论；
2. 检查 AI 总结是否和原文一致；
3. 找到真正支持结论的原文位置；
4. 如果论文没有说过，就标记“证据不足”。

提交格式：

```text
待核对结论：
支持 / 反驳 / 证据不足：
论文标题：
原文页码或章节：
支持判断的原文内容：
你的说明：
```

不要因为“这句话听起来合理”就判定为正确。

### 任务 C：设计测试题

适合：对项目主题有一定理解、喜欢出题的同学。

一条测试题需要包括：

```text
学习者类型：本科生 / 研究生 / 企业人员
问题：
正确答案应包含哪些要点：
每个要点来自哪篇论文：
允许回答“证据不足”吗：
难度：1-5
为什么这样定难度：
```

好的问题应该：

- 能从指定论文中找到证据；
- 不是只靠常识就能回答；
- 能检查 AI 是否乱说、漏说或引用错论文；
- 答案不是由出题的 AI 自己说了算。

### 任务 D：盲评 AI 答案

适合：愿意做判断、但不想写代码的同学。

负责人会给你一份隐藏系统名称的答案。你只需要评分：

| 项目 | 评分 |
| --- | --- |
| 是否回答了问题 | 1-5 |
| 结论是否有论文支持 | 1-5 |
| 引用是否真的支持对应句子 | 1-5 |
| 是否遗漏关键知识点 | 1-5 |
| 难度是否适合目标学习者 | 1-5 |
| 是否容易阅读 | 1-5 |

如果发现事实错误，请写出对应句子和原因。

不要猜答案来自哪个系统，也不要因为页面好看就提高分数。

### 任务 E：运行实验

适合：会一点命令行或愿意照步骤操作的同学。

你需要做：

1. 使用负责人给定的配置；
2. 运行已经写好的测试脚本；
3. 记录成功、失败、耗时和异常；
4. 保存完整结果；
5. 不修改测试答案，不删除失败结果。

遇到报错时：

- 保存报错信息；
- 记录运行到哪一步；
- 告诉负责人；
- 不要为了让数字好看而跳过失败案例。

## 哪些工作可以让 AI 帮忙

可以让 AI：

- 整理论文格式；
- 生成摘要初稿；
- 推荐候选证据句；
- 生成候选测试题；
- 检查表格有没有漏填；
- 汇总实验结果；
- 写报告初稿。

但下面这些必须由人确认：

- 论文是不是真的；
- 论文是否真的支持某个结论；
- 正确答案是什么；
- 数据是否允许使用；
- 是否真的达到“幻觉率低于 5%”；
- 是否可以宣传“首创”“领先”“零幻觉”。

一句话：

> AI 可以帮我们做草稿，不能替我们签字。

## 我们绝对不要做什么

- 不编造论文、作者、实验数据或用户反馈；
- 不把 AI 生成的答案直接当成标准答案；
- 不只挑成功案例展示；
- 不删除表现不好的实验结果（这可以写到我们的改进展望里）；
- 没有证据时不宣传“首创”“零幻觉”。

## 一次完整工作的样子

1. 同学 A 找到论文并核对链接；
2. AI 生成论文笔记初稿；
3. 同学 B 检查摘要和证据句；
4. 同学 C 根据论文设计问题；
5. 两位同学分别给出正确答案和证据；
6. 有分歧时由第三个人裁决；
7. 脚本让不同版本的系统回答同一批问题；
8. 同学 D 在不知道系统名称的情况下评分；
9. 脚本汇总数字；
10. 负责人检查后写进比赛报告。

## 每个人需要投入多少时间

第一轮不会让大家长期做重复劳动。

建议每人先完成一个小任务：

| 任务 | 第一次预计时间 |
| --- | --- |
| 找 5 篇论文 | 30-45 分钟 |
| 核对 3 条结论 | 30-60 分钟 |
| 设计 3 道测试题 | 30-60 分钟 |
| 盲评 10 份答案 | 30-45 分钟 |
| 运行一组固定实验 | 20-40 分钟 |

第一轮的目的，是看看流程是否顺畅，而不是马上做出很大的数据集。
