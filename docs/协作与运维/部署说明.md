# 部署说明

## 1. 环境要求

- Windows、macOS 或 Linux；
- Python 3.11 及以上；
- 一个现代浏览器；
- 离线 Mock 不需要 Node.js、模型 API 或联网环境；Web 账号与实验留存使用
  Python 标准库 SQLite，不需要单独安装数据库服务；
- 实时研究模式需要可访问 OpenAlex、Crossref、arXiv、官方文档和所选模型供应商，
  可由用户提供模型 API Key，或由服务器为登录用户提供免费 DeepSeek。

## 2. 本地启动

Windows PowerShell：

```powershell
$env:PYTHONPATH="src"
python -m yanhai --host 127.0.0.1 --port 8765
```

macOS / Linux：

```bash
PYTHONPATH=src python -m yanhai --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765`。健康检查地址为：

```text
http://127.0.0.1:8765/api/health
```

公开注册默认关闭。本地首次建立账号前设置：

```powershell
$env:YANHAI_REGISTRATION_OPEN="1"
```

Linux 使用 `YANHAI_REGISTRATION_OPEN=1`。数据库默认写入
`outputs/runtime/yanhai.sqlite3`；长期运行应设置 `YANHAI_DATA_DIR`。

## 3. 可选安装

也可以在虚拟环境中以可编辑模式安装：

```bash
python -m venv .venv
python -m pip install -e .
yanhai
```

运行时无第三方 Python 依赖；`setuptools` 仅用于可选安装。

## 4. 核心 API

| 方法 | 路径 | 用途 |
| --- | --- | --- |
| GET | `/api/health` | 服务健康状态 |
| GET | `/api/auth/status`、`/api/auth/me` | 注册开关、登录状态与用户画像 |
| GET | `/api/profiles` | 获取当前登录用户画像 |
| GET | `/api/providers` | 获取可用供应商、默认模型和协议 |
| GET | `/api/knowledge-base` | 获取文献与关系切片 |
| GET | `/api/library/slices` | 获取 SQLite 垂直领域切片统计 |
| GET | `/api/history`、`/api/study/status` | 获取当前用户历史或实验统计 |
| POST | `/api/auth/register`、`/api/auth/login`、`/api/auth/logout` | 账号会话 |
| POST | `/api/provider/test` | 使用本次提交的 Key 做最小连接测试 |
| POST | `/api/run` | 运行完整协同闭环 |
| POST | `/api/feedback` | 基于反馈重算资源 |
| POST | `/api/experiments/run` | 运行并保存 A/B/C/Full Mock 对照 |
| POST | `/api/surveys` | 保存实验问卷 |
| PUT | `/api/profile` | 保存新的画像版本 |

运行示例：

```json
{
  "query": "多智能体科研推理如何降低幻觉？",
  "preset": "full",
  "llm": {
    "provider": "mock",
    "model": "offline-rules"
  }
}
```

实时模式示例（不要把真实 Key 写入代码、文档或版本控制）：

```json
{
  "query": "多智能体科研推理如何降低幻觉？",
  "preset": "full",
  "llm": {
    "provider": "openai",
    "model": "gpt-5.6-terra",
    "api_key": "<本次请求的 API Key>"
  }
}
```

Web 登录后自动使用当前用户的版本化画像，不再信任请求体中的合成
`profile_id`。`provider` 可取 `mock`、`free-deepseek`、`deepseek`、
`openai`、`anthropic` 或 `kimi`。
远程供应商的 Key 只在单次请求内使用，服务端不持久化，也不会在响应中回传。
`free-deepseek` 无需用户提交 Key；服务端把它转换为 DeepSeek 请求并注入托管 Key。

反馈示例：

```json
{
  "query": "多智能体科研推理如何降低幻觉？",
  "feedback": "too_hard"
}
```

`feedback` 可取 `too_hard`、`suitable` 或 `too_easy`。

## 6. 现场演示建议

- 提前启动本地服务并检查 `/api/health`；
- 现场优先使用离线 Mock，避免公网或模型 API 波动；
- 准备本科生与企业分析师两条不同演示路径；
- 保留命令行输出作为浏览器异常时的后备；
- 正式版接入大模型后，仍保留当前规则基线作为离线降级路径。

## 7. 密钥与部署边界

- 不要把 API Key 写入 `localStorage`、源码、截图、日志或测试夹具；
- 当前本地服务器是 HTTP，只有绑定 `127.0.0.1` 时才适合输入个人 Key；
- 若使用 `--host 0.0.0.0` 或部署到服务器，必须在反向代理层启用 HTTPS，
  并增加请求限流；
- 服务端 DeepSeek Key 当前从项目根目录 `secret/DeepSeekAPI.txt` 读取，文件应设为
  仅服务用户可读、不得提交或打包，替换后重启服务才会生效；
- Cookie 在公网必须设置 `YANHAI_COOKIE_SECURE=1`；子路径部署可设置
  `YANHAI_COOKIE_PATH=/AgentDemo/start/`；
- 公开注册必须显式设置 `YANHAI_REGISTRATION_OPEN=1`；正式公网开放前先补齐
  注册限流、邮箱验证、密码找回、隐私同意和数据删除；
- 供应商错误会经过清洗后返回，应用不回显请求头或 API Key。

## 8. snowsong.top 验证部署

项目已经为子路径部署做了相对资源与 API 基址适配。腾讯云验证环境采用：

- `https://snowsong.top/AgentDemo/start/`：Nginx 反代 Python Web 服务；
- `https://snowsong.top/AgentDemo/install/`：Nginx 静态托管 Qt 发行 ZIP；
- Python 仅绑定 `127.0.0.1:8765`，公网入口统一经过现有 HTTPS；
- systemd 以独立低权限用户运行，Nginx 对 API 请求限流。
