# 部署说明

## 1. 当前定位

当前服务是面向竞赛现场和小规模评审的单进程 Demo Harness，不是可直接承载公网多租户的生产集群。它只依赖 Python 3.11+ 标准库，但已具备有界并发、任务超时、幂等、运行日志、统一错误、健康/就绪探针、在线 RAG 重试熔断和优雅退出等工程护栏。

## 2. 环境要求

- Windows、macOS 或 Linux；
- Python 3.11 及以上；
- 一个现代浏览器；
- 离线 Mock 不需要数据库、Node.js、模型 API 或联网；
- 实时研究模式需要可访问 OpenAlex、Crossref、arXiv、官方文档和所选模型供应商，并由用户提供模型 API Key。

## 3. 本地启动

Windows PowerShell：

```powershell
$env:PYTHONPATH="src"
python -m yanhai --host 127.0.0.1 --port 8765
```

macOS / Linux：

```bash
PYTHONPATH=src python -m yanhai --host 127.0.0.1 --port 8765
```

打开 `http://127.0.0.1:8765`。若 `localhost` 在演示机上优先解析到不可用的 IPv6，请始终使用 `127.0.0.1`；服务默认显式绑定 IPv4。

### 一键启动（Windows）

交给其他人使用时，先完整解压，然后双击根目录 `RUN_DEMO.bat`。启动器会寻找 `python` 或 Windows `py -3`，启动后端、执行最多 12 秒健康检查并自动打开浏览器；结束时双击 `STOP_DEMO.bat`。

PowerShell 等价命令：

```powershell
.\scripts\launch_demo.ps1          # 启动并自动打开浏览器
.\scripts\launch_demo.ps1 -NoBrowser
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\start_demo.ps1           # 前台启动
.\scripts\start_demo.ps1 -Background -StartupTimeoutSeconds 10  # 立即返回终端
```

后台模式不重定向长期子进程输出句柄，并在 10 秒内轮询健康状态；启动失败会自动终止子进程并返回错误，不会无限等待。脚本先找系统 `python`，其次 `py -3`，最后才尝试 Codex 工作区内置 Python。

## 4. 可选安装

也可以在虚拟环境中以可编辑模式安装：

```bash
python -m venv .venv
python -m pip install -e .
yanhai
```

运行时无第三方 Python 依赖；`setuptools` 仅用于可选安装。

## 5. 启动后的三步确认

```powershell
Invoke-RestMethod http://127.0.0.1:8765/api/health
Invoke-RestMethod http://127.0.0.1:8765/api/ready
$env:PYTHONPATH="src"
python scripts/smoke_test_backend.py
```

- `/api/health`：进程是否存活；
- `/api/ready`：画像、垂直语料、schema、前端资产是否可用；
- 冒烟脚本：运行一次完整三智能体闭环并确认幂等重放。

## 6. 容器部署

```bash
docker compose up --build -d
docker compose ps
```

Compose 只把容器端口发布到宿主机 `127.0.0.1:8765`，不发布到整个局域网；日志摘要和 OpenAlex 缓存写到宿主机 `outputs/`。停止：`docker compose down`。

`Dockerfile` 默认以非 root 用户运行，并且在尝试绑定 `0.0.0.0` 时 fail-closed：必须配置 Bearer Token，或像当前 Compose 一样在确认宿主机只发布回环端口后显式设置 `YANHAI_ALLOW_REMOTE_WITHOUT_TOKEN=true`。

## 7. 制作交付 ZIP

```powershell
Set-ExecutionPolicy -Scope Process Bypass
.\scripts\package_demo.ps1
```

默认生成 `dist/yanhai-demo-windows.zip`，包含运行所需的 `src/`、`web/`、`data/`、`config/`、启动脚本、文档和测试；不包含 `.git`、当前运行日志、PID 文件或本机缓存。压缩包根目录还包含 `GITHUB_REPOSITORY.url`，评审双击即可打开公开源码仓库的默认 `main` 分支。

## 8. 接收者如何运行（离线分发）

### Windows 双击方式（推荐）

1. 安装 Python 3.11+，安装时勾选 `Add Python to PATH`；
2. 完整解压 ZIP，不能直接在压缩软件预览窗口中运行；
3. 双击 `RUN_DEMO.bat`，最多等待 12 秒健康检查通过后自动打开 `http://127.0.0.1:8765/`；
4. 选择领域和学习者画像，点击“开始协同推理”；
5. 使用结束后双击 `STOP_DEMO.bat`。

如果安全策略阻止自动打开浏览器，启动窗口会保留并显示地址，此时双击同目录的 `OPEN_DEMO.url` 或手动输入地址；后端不受影响。基础 Demo 只依赖 Python 标准库；离线时除“OpenAlex 联网扩展”按钮外，其余核心链路可运行。

### Docker 方式

已安装 Docker Desktop 的机器：`docker compose up --build -d`，访问 `http://127.0.0.1:8765/`，结束后 `docker compose down`。

### 常见故障

| 现象 | 原因与处理 |
|---|---|
| 提示找不到 Python | 安装 Python 3.11+ 并勾选 PATH；重新打开文件夹后再双击 |
| 页面“拒绝建立连接” | 确认黑色启动窗口没有报错；地址用 `127.0.0.1`，不要改 `localhost` |
| 端口 8765 被占用 | 先双击 `STOP_DEMO.bat`；若服务非本启动器创建，关闭占用该端口的软件 |
| 服务已就绪但浏览器没打开 | 双击 `OPEN_DEMO.url` 或手动访问；启动窗口会显示原因 |
| 双击后被安全软件拦截 | 用 PowerShell 命令行方式运行，或改用 Docker；不要关闭整机安全防护 |
| 页面能打开但在线扩展失败 | 联网 RAG 有超时和熔断；核心离线数据不受影响 |
| 在 ZIP 内双击无反应 | 必须先“全部解压”，脚本依赖相对目录结构 |

### 交付前检查清单

```powershell
$env:PYTHONPATH="src"
python -m unittest discover -s tests -v
python scripts/build_demo_assets.py
.\scripts\launch_demo.ps1 -NoBrowser
python scripts/smoke_test_backend.py
.\scripts\stop_demo.ps1
.\scripts\package_demo.ps1
```

最后在一台没有项目源码历史、没有 Codex 环境的干净 Windows 机器上解压 ZIP 并双击运行一次。只有这一步通过，才能称为“其他人可使用的 Demo”。

## 9. 是否必须做成应用程序

不必须。Demo 的交付目标是“可复现、可讲解、可验证”，浏览器界面加本地后端已满足。现在重写 Qt/C# 会复制一套 UI、引入打包差异并挤占知识抽取与实验时间。

如主办方明确要求单个可执行文件：

1. 保留现有后端和 Web UI；
2. 用 PyInstaller 把 Python 解释器、`src/`、`web/`、`data/` 与 `config/` 打包；
3. EXE 启动本地服务并拉起默认浏览器；
4. 在干净的 Windows 10/11 虚拟机中验证启动、停止和杀毒软件兼容性。

Qt/PySide6 只在必须呈现原生窗口或离线终端管控严格时再加“壳”。

## 10. 核心 API

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 存活探针 |
| GET | `/api/ready` | 就绪探针 |
| GET | `/api/metrics` | 进程级请求、失败、延迟、事件和熔断状态 |
| GET | `/api/profiles` | 合成画像 |
| GET | `/api/providers` | 可用供应商、默认模型和协议 |
| GET | `/api/knowledge-base` | 文献与关系切片 |
| GET | `/api/extracted-graph` | 可追溯图谱 |
| GET | `/api/ablation` | 决策消融 |
| POST | `/api/provider/test` | 使用本次提交的 Key 做最小连接测试 |
| POST | `/api/run` | 完整三智能体闭环 |
| POST | `/api/feedback` | 反馈后重算 |
| POST | `/api/graph-query` | 意图感知、概念图检索与论文推荐 |
| POST | `/api/online-rag` | OpenAlex 候选扩展 |

### 运行示例

离线模式：

```json
{
  "profile_id": "graduate_cross_domain",
  "query": "多智能体科研推理如何降低幻觉？",
  "llm": { "provider": "mock", "model": "offline-rules" }
}
```

实时模式（不要把真实 Key 写入代码、文档或版本控制）：

```json
{
  "profile_id": "graduate_cross_domain",
  "query": "多智能体科研推理如何降低幻觉？",
  "llm": {
    "provider": "openai",
    "model": "gpt-5.6-terra",
    "api_key": "<本次请求的 API Key>"
  }
}
```

`provider` 可取 `mock`、`deepseek`、`openai`、`anthropic` 或 `kimi`。远程供应商的 Key 只在单次请求内使用，服务端不持久化，也不会在响应中回传。

反馈示例（`feedback` 取 `too_hard`、`suitable`、`too_easy`）：

```json
{
  "profile_id": "graduate_cross_domain",
  "query": "多智能体科研推理如何降低幻觉？",
  "feedback": "too_hard"
}
```

### 可靠性协议

每个响应带 `X-Request-ID`；成功写请求另带 `X-Run-ID`。客户端可传入 `Idempotency-Key`：相同键 + 相同请求体重放首次成功结果（返回 `Idempotency-Replayed: true`）；同一键 + 不同请求体返回 409，避免错误复用结果。

PowerShell 发送中文 JSON 必须显式编码为 UTF-8 字节；服务端拒绝声明为非 UTF-8 的 JSON，若查询含典型 C1 乱码控制符则返回 `400 invalid_encoding`，不让意图智能体静默回退到默认路由。

统一错误体：

```json
{
  "error": {
    "code": "server_busy",
    "message": "The bounded task queue is full. Retry shortly.",
    "retryable": true,
    "request_id": "req_..."
  }
}
```

## 11. 环境变量

完整模板见 `deploy/demo.env.example`。关键配置：

| 配置 | 默认值 | 作用 |
|---|---:|---|
| `YANHAI_MAX_WORKERS` | 4 | 同时执行的耗时任务上限 |
| `YANHAI_MAX_QUEUED_TASKS` | 4 | 等待队列上限；满后返回 429 |
| `YANHAI_TASK_TIMEOUT_SECONDS` | 20 | 任务级 deadline；超时返回 504 |
| `YANHAI_MAX_BODY_BYTES` | 1000000 | 请求体上限；超限返回 413 |
| `YANHAI_IDEMPOTENCY_TTL_SECONDS` | 300 | 写请求结果重放窗口 |
| `YANHAI_ONLINE_TIMEOUT_SECONDS` | 5 | 单次 OpenAlex 请求超时 |
| `YANHAI_ONLINE_RETRIES` | 1 | OpenAlex 瞬态失败重试次数 |
| `YANHAI_CIRCUIT_FAILURE_THRESHOLD` | 3 | 熔断开启阈值 |
| `YANHAI_API_TOKEN` | 空 | 非回环部署所需 Bearer Token |

不要把真实 Token 写进仓库或日志。当前 Web 页面按本地无 Token 演示设计；若启用 Token，应在反向代理层注入认证，不要把长期密钥写入前端 JavaScript。

## 12. 状态、日志与恢复

- 标准输出：一行一个 JSON 事件（时间、请求 ID、路由、状态、延迟），不记录原始查询或 Token；
- `outputs/run-journal.jsonl`：运行 ID、查询哈希、画像 ID、耗时、命题状态数和 Agent 数，默认达到 5 MB 后单份轮转；
- `outputs/openalex-cache.json`：联网 RAG 成功结果的原子缓存；网络故障或熔断时回退；
- 幂等缓存当前位于单进程内存，重启后失效。


## 14. 现场演示建议

- 提前启动本地服务并检查 `/api/health`；
- 现场优先使用离线 Mock，避免公网或模型 API 波动；
- 准备本科生与企业分析师两条不同演示路径；
- 保留命令行输出作为浏览器异常时的后备；
- 正式版接入大模型后，仍保留当前规则基线作为离线降级路径。

## 15. 密钥与部署边界

- 不要把 API Key 写入 `localStorage`、源码、截图、日志或测试夹具；
- 当前本地服务器是 HTTP，只有绑定 `127.0.0.1` 时才适合输入个人 Key；
- 若使用 `--host 0.0.0.0` 或部署到服务器，必须在反向代理层启用 HTTPS 并增加请求限流；若增加账户或服务端 Key 代管，再加入用户身份认证和加密存储；
- 供应商错误会经过清洗后返回，应用不回显请求头或 API Key。

## 16. 从 Demo 到正式生产仍需补齐

1. 用 FastAPI/ASGI 或等价框架实现真正可取消的异步 I/O 和流式输出；
2. 把幂等、会话和任务状态迁移到 Redis/PostgreSQL；
3. 接入 OpenTelemetry、Prometheus/Grafana 和集中日志；
4. 把模型 Token、耗时、重试次数和预算纳入 run-level 成本指标；
5. 使用反向代理完成 TLS、用户认证、速率限制和请求审计；
6. 多副本前先建立共享任务队列与一致性协议，避免把内存状态错误扩展到分布式环境。

因此，当前结论是“竞赛 Demo 后端具备可复现、可观察、能降级的工程基线”，不是“已经达到生产级”。

## 17. snowsong.top 验证部署
