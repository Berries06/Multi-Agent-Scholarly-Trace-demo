# “研海寻踪”申报书与论文统一格式

版本：v0.1（2026-07-26）  
用途：团队后续写作、素材归档、评审自检的唯一内部格式基线。赛事官方通知、匿名要求和下发模板始终具有最高优先级。

## 1. 最终交付物

| 编号 | 交付物 | 编辑源文件 | 正式交付 | 建议体量 | 核心目的 |
|---|---|---|---|---|---|
| A | 挑战杯申报书/成果汇报书 | `submission/研海寻踪_申报书.docx` | PDF/A4 | 正文 45–60 页，附录另计 | 证明问题价值、技术完整性、创新性和落地能力 |
| B | 研究论文 | `paper/main.tex` 或 `paper/研海寻踪_论文.docx` | PDF/A4 | 正文 8–12 页或 8,000–12,000 字 | 证明信息抽取与图谱构建方法有效 |
| C | 证据附件 | 数据说明、标注指南、测试报告、软著/专利材料、演示说明 | PDF/ZIP | 不限 | 支撑申报书中的每项可核查主张 |
| D | 可复现实验包 | 固定数据划分、配置、日志、指标与代码版本 | 仓库 tag/ZIP | 不限 | 让评委能够复核核心结果 |

禁止把“首创”“显著优于”“已产业化”“自主知识产权”等表述写入定稿，除非已经有查新、统计检验、合同、软著或专利材料支撑。

## 2. 申报书格式

### 2.1 内部排版基线

两份参考样例均采用 A4。第二份样例明确“除标题外，正文宋体、小四、1.5 倍行距”，因此项目内部先采用以下可执行标准；拿到本届官方模板后只改样式，不改内容层级。

| 项目 | 内部标准 |
|---|---|
| 纸张与页边距 | A4；上/下 2.54 cm，左/右 2.8 cm |
| 中文正文 | 宋体，小四（12 pt），1.5 倍行距，首行缩进 2 字符 |
| 英文与数字 | Times New Roman，12 pt |
| 一级标题 | 黑体，小二或三号，章前分页 |
| 二级标题 | 黑体，四号 |
| 三级标题 | 黑体，小四 |
| 图题/表题 | 宋体五号；图题置图下，表题置表上，全文连续编号 |
| 公式 | 居中，右侧按章编号，如“式（4-2）” |
| 页眉页脚 | 项目简称、章节名、连续页码；匿名评审版删除身份信息 |
| 引用 | 正文顺序编码 `[1]`，参考文献建议 GB/T 7714—2015；若赛事另有格式则覆盖 |

### 2.2 申报书目录与页数预算

| 部分 | 建议页数 | 必须回答的问题 |
|---|---:|---|
| 封面、摘要、关键词 | 2 | 做什么、解决什么、核心结果是什么 |
| 评审指标索引表 | 1–2 | 每个评分项对应哪一节、哪张表、哪项附件 |
| 1. 项目背景与需求证据 | 4–5 | 文献碎片化的真实规模、现有工具为何不足 |
| 2. 国内外研究与竞品 | 5–7 | 学术方法与产品分别做到哪里，缺口是什么 |
| 3. 研究问题与总体方案 | 3–4 | 研究对象、任务定义、假设和端到端技术路线 |
| 4. 科研文献信息抽取方法 | 10–14 | 解析、实体、关系、消歧、证据、多智能体校验如何实现 |
| 5. 动态知识图谱与发现方法 | 6–8 | 融合、演化、冲突、蓝海计算如何定义 |
| 6. 系统实现 | 5–7 | 模块、数据流、接口、部署、性能和安全 |
| 7. 实验设计与结果 | 8–12 | 数据集、基线、主结果、消融、误差和显著性 |
| 8. 创新点与知识产权 | 3–4 | 创新相对谁成立，证据是什么，权属如何 |
| 9. 应用价值与实施计划 | 4–6 | 用户、场景、试点、成本、风险和可持续路径 |
| 10. 总结、局限与展望 | 2–3 | 当前边界、失败案例、下一阶段 |
| 参考文献、附录 | 按需 | 来源完整、图表可复核、材料可追溯 |

第 4、5、7 章是本项目的技术核心，三章合计不应少于正文的 40%。前端截图只能放在第 6 章，不能替代方法和实验。

### 2.3 摘要模板

摘要控制在 500–800 字，按“痛点—方法—实验—结果—价值”写成一个完整闭环：

1. 痛点：跨论文实体别名、跨句关系、表格结果和学术争议难以结构化。
2. 方法：结构感知解析、schema 约束抽取、实体融合、提出者—批判者—裁判校验和动态知识图谱。
3. 实验：说明自建/公开数据、基线、核心指标和盲审方式。
4. 结果：只写已经复现实验得到的数值，附置信区间或显著性检验。
5. 价值：面向高校科研选题和企业技术情报的具体收益。

关键词建议 5–7 个：科研知识图谱；科学信息抽取；文档级关系抽取；实体消歧；多智能体博弈；证据溯源；研究发现。

### 2.4 评审指标索引表

申报书目录之后固定放置下表，并在定稿阶段填写页码：

| 评审维度 | 核心主张 | 正文位置 | 直接证据 | 附件/代码 |
|---|---|---|---|---|
| 完整性 | 完成 PDF 到可追溯图谱的闭环 | 第 3–6 章 | 架构图、接口测试、演示录像 | tag、测试报告 |
| 技术性能 | 抽取、消歧和图谱质量达到目标 | 第 7 章 | P/R/F1、证据命中率、人工复核结果 | 固定测试集、日志 |
| 创新性 | 多智能体批判与裁决降低错误入图 | 第 4、8 章 | 对照实验与消融实验 | 实验配置 |
| 实用性 | 支撑演化溯源、争议捕获、蓝海发现 | 第 5、9 章 | 用户任务完成率、案例研究 | 试点记录 |
| 可信性 | 每条关系可回指论文原句/页码 | 第 4、7 章 | 证据绑定完整率、证据跨度 F1、错误案例 | 图谱导出、审计记录 |

## 3. 研究论文格式

### 3.1 论文定位

论文不写成产品说明书，中心命题固定为：

> 面向跨学科科研文献，schema 约束的文档级信息抽取与“提出者—批判者—裁判”校验，能否在保持证据可追溯的同时，提高知识图谱三元组的准确率、跨文档融合质量和下游发现效用？

### 3.2 论文结构

| 章节 | 内容 |
|---|---|
| 标题、摘要、关键词 | 中英文题名；中文摘要 300–500 字；英文摘要语义一致；4–6 个关键词 |
| 1. 引言 | 问题、缺口、研究问题、贡献列表 |
| 2. 相关工作 | 科学 IE、文档级 RE、实体链接/KG 融合、GraphRAG、多智能体校验 |
| 3. 任务定义 | 输入、实体/关系 schema、证据跨度、图谱输出、符号定义 |
| 4. 方法 | 文档解析、候选抽取、实体消歧、关系抽取、批判与裁决、图融合 |
| 5. 数据与标注 | 数据来源、许可、抽样、指南、双人标注、一致性和划分 |
| 6. 实验设置 | 基线、实现细节、评价指标、统计方法、硬件与成本 |
| 7. 结果与分析 | 主结果、分领域结果、消融、鲁棒性、效率、案例 |
| 8. 局限与伦理 | 版权、隐私、偏差、错误传播、人工复核边界 |
| 9. 结论 | 回答研究问题，不新增未验证主张 |
| 参考文献与附录 | 完整引用；提示词、schema、更多结果和复现说明放附录 |

目标会议/期刊确定后，必须直接套用其 Word/LaTeX 模板；未确定前采用 A4、双栏论文草稿，图表与参考文献格式保持可自动迁移。

### 3.3 最低实验矩阵

| 类别 | 必做对照 |
|---|---|
| 抽取基线 | 规则词典；通用 LLM 单次抽取；DeepKE/OneKE 或同类监督模型；本项目完整方法 |
| 文本范围 | 仅标题摘要 vs. 全文；纯文本 vs. 加入表格 |
| 消融 | 去 schema；去实体融合；去批判者；去裁判；去证据一致性检查 |
| 泛化 | 同领域测试 vs. 跨领域/OOD 测试 |
| 人工评测 | 至少两名标注者；盲评三元组正确性、证据充分性、发现有效性 |
| 效率 | 单篇耗时、显存/内存、API token 或人民币成本、增量更新耗时 |

核心指标至少包括实体严格/宽松 F1、关系 micro/macro F1、实体链接准确率、证据跨度 F1、三元组精确率、图谱重复率、冲突识别 F1 和下游问题回答正确率。所有百分比同时报告分子/分母；关键结果至少运行 3 次并报告均值与标准差。

## 4. 素材与版本管理

每个可量化主张建立一条“主张—实验—图表—代码—提交”链路：

```text
claim_id
  ├─ experiment_id
  ├─ dataset_version
  ├─ config_hash
  ├─ git_commit
  ├─ result_file
  └─ figure/table_id
```

图表禁止手工改数；应由 `outputs/` 中的原始结果生成。训练集、验证集、测试集一经论文主实验确定，不得通过观察测试集结果反复调整。任何人工修订三元组都必须记录操作者、时间、原值、改后值和理由。

## 5. 定稿检查

- 申报书中的每项“创新”都指明对比对象和实验证据。
- 方法章能让同领域同学据此复现，不用猜提示词、阈值或 schema。
- 所有图、表、公式、章节、参考文献均被正文引用。
- 数据来源、许可、论文版权和个人信息处理有明确说明。
- 每条展示关系可点击回到论文、章节、原句，最终补齐页码或边界框。
- 匿名版、实名版分别导出并逐页检查。
- 申报书、论文、演示口径使用同一组已冻结的实验数字。
