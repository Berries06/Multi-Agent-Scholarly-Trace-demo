## 5. 已采纳落地细节

### 5.1 Docling

- 以统一文档对象隔离 PDF/DOCX 解析与下游抽取；
- 可选 `DoclingParser` 使用官方 `DocumentConverter` 接口，转换 Markdown 后映射到 `ScientificDocument`；
- `pyproject.toml` 新增可选依赖组 `documents`，默认离线演示不强制安装重型模型。

落地：`src/yanhai/extraction.py`、`pyproject.toml`。限制：页码、版面框、表格单元格和公式对象仍需从 lossless JSON 进一步映射。

### 5.2 DeepKE

- 采用“Data / Model / Core”和实体/关系任务分离的模块化思想；
- 用版本化 schema 固定实体/关系类型与别名，候选生成器可替换，批判与裁决层不随模型更换；
- 实验计划纳入标准、低资源、文档级和中英双语场景。

落地：`data/knowledge/extraction_schema.json`、`src/yanhai/extraction.py`、`tests/test_extraction.py`。限制：未复制模型源码或训练依赖；下一阶段在独立可选环境接入并做同测试集对照。

### 5.3 Microsoft GraphRAG

- 将已接收关系组织成实体社区，为全局问题与领域摘要预留接口；
- 对齐 BYOG 数据契约：`entities/relations/evidence/communities` 映射到 GraphRAG `entities/relationships/text_units/communities`；
- 借鉴查询分工：广度覆盖论文检索、深度证据路径分析、DRIFT-like 社区起点 Idea 发现；
- 图边保留来源证据、置信度和状态，索引前先做实体融合和关系裁决；
- 索引成本、提示词适配和查询效果列入实验，不默认宣称 GraphRAG 更好。

落地：`src/yanhai/extraction.py`、`src/yanhai/graph_rag.py`。限制：当前社区算法是无外部依赖的连通分量基线，不是官方 Global/Local Search；正式实验需通过 BYOG 接入 Leiden 社区、community reports 和 embeddings。

## 6. 最终模型路线

### 提出者

- 现场离线：schema-guided pattern baseline；
- 第一优先：`urchade/gliner_medium-v2.1` + `jackboyla/glirel-large-v0`；
- 监督对照：SciBERT/DyGIE++ 或 DeepKE；
- 结构化 LLM：`Qwen/Qwen2.5-7B-Instruct`，只补充候选。

### 批判者

- 现场离线：证据 ID、跨度覆盖、schema 类型、强断言和共现检查；
- 模型升级：SciFact/MultiVerS verifier，以本地证据跨度为 premise；
- 外部检索：发现相反证据时追加 CONTRADICTS，不覆盖原边。

### 裁判

- 不使用与提出者相同的自由生成过程；
- 在验证集上校准逻辑回归、梯度提升或加权规则；
- 输入候选分、跨度分、类型一致性、来源独立性、批判风险；
- 报告 ECE、Brier、precision/recall/UAR，而非只报告“置信度”。

当前模型接入以 `src/yanhai/providers.py` 的提供方注册表和 `config/实验/experiment_models.json` 的实验快照为准。

## 8. 理论表述

对候选关系 \(r\)、证据 \(e\) 和约束违反向量 \(v\)，裁判估计：

```text
P(correct_relation ∧ sufficient_evidence | r, e, v)
```

提出者以召回为目标，批判者以发现风险为目标，裁判以受约束决策为目标：

```text
maximize VTY
subject to accepted_precision >= 0.90
           relation_evidence_coverage = 1.00
```

三者产生增益的必要条件是信息或目标异质性；如果共享同一模型、同一证据和同一错误模式，多数投票只会放大相关错误。因此正式论文必须同时报告同质多智能体和异构多智能体对照。
