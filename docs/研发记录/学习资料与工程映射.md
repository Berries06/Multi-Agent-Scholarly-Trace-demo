## 3. 推荐实现顺序

### P0：先建立可验证的 Agent 内核

1. 定义统一 `AgentMessage` 和 `AgentResult`，所有消息必须能追溯到运行、角色和证据。
2. 抽象 `ModelProvider`，保留 `OfflineRuleProvider`，再增加 CAMEL/LLM Provider。
3. 增加 `ResearchPlan`、子任务状态与共享 `EvidenceNote`，形成“规划—检索—总结—裁决—报告”链路。
4. 批判者支持反证检索和有限轮修订；质量模块记录接受、退回或拒绝的可解释原因。
5. 扩充评测到准确性、效率、鲁棒性、协作性四维，并保留原始运行轨迹。

### P1：增强交互与知识能力

1. 通过 SSE 流式展示子任务、智能体状态和中间证据。
2. 加入向量检索、重排、短期记忆和长期知识图谱，但统一经过现有知识库接口。
3. 增加 CAMEL `RolePlaying` 实验适配器，和自研编排器使用同一输入输出协议。
4. 增加技术演化、学术争议、研究蓝海三类任务模板。

### P2：形成参赛证据

1. 建立不少于 50 组画像—任务—资源金标准。
2. 完成单 Agent、普通 RAG、无批判者多 Agent、完整系统的消融。
3. 记录正确率、引用质量、覆盖率、时延、成本、恢复率与专家评分。
4. 固化可重复演示、部署说明、数据来源、许可证和知识产权材料。

## 4. 学习完成的判断标准

学习不是“读完章节”，而是每个概念至少对应一项可运行产物：

- 角色协作：同一任务能输出完整消息轨迹；
- 反思与批判：植入无证据断言后能被拦截或退回；
- Deep Research：能显示子任务及其证据笔记；
- RAG/上下文：每个进入报告的结论均保留来源 ID；
- 评测：同一数据集能重复比较四种系统配置；
- 工程交付：无外网时仍能使用离线 Provider 完成核心演示。
