## 2. 从 100 篇论文得到的八类共同缺口

| 主题 | 已有工作已经做好 | 仍普遍没有闭环的部分 | 对本项目的约束 |
|---|---|---|---|
| 科学信息抽取 | 实体、关系、事件、跨句与开放标签抽取持续进步 | 抽取置信不等于证据充分；关系进入图后缺少可逆状态和证据谱系 | 抽取器只能产生 candidate，不能直接写入 accepted graph |
| 科学主张核验 | claim–evidence 检索、支持/反驳分类和长文本事实评分已有成熟基线 | 科学模态、条件、时态、跨论文冲突和证据删除后的状态迁移仍分散 | 状态机必须显式保存条件、时间、来源和历史决策 |
| Agentic RAG | 查询分解、主动检索、自反思、图检索和长文生成已很拥挤 | 检索相关性仍不等于蕴含；同一模型的自评容易产生相关性错误 | 检索器、验证器和 hard guard 要分离，禁止静默自证 |
| 多智能体 | 辩论、共识、角色 SOP、异质模型和工具 Agent 已有大量先例 | 性能高度依赖任务、停止规则与多样性，且常不胜过 self-consistency | 不能以 Agent 数量为贡献；必须测信息独立性、成本和失败切片 |
| GraphRAG 与时序图谱 | 局部/全局图检索、PPR、多跳、时间预测已有强方法 | 建图错误会传播；多数图不保留原文跨度、裁决历史和 supersession 语义 | SQLite 保持事实源，图索引可重建；关系节点要绑定证据事件 |
| 个性化与知识追踪 | DKT、SAKT、AKT、pyKT、LLM 教学和自适应题目生成已成熟 | 多数状态仍是知识点答对概率，较少建模“能否正确使用科研证据” | 不把静态画像文案变化写成个性化效果；改测证据素养状态 |
| 评测与复现 | 事实性、校准、选择性预测、Agent benchmark 和 run artifacts 均有规范 | LLM-as-judge、合成数据、重复重放经常被误当真人金标准或独立样本 | 每个数字必须标注 gold/proxy、样本量、哈希、区间和 claim ceiling |
| 科研系统 | OpenScholar、PaperQA2、Virtual Lab 等已展示强检索或团队科研能力 | 大规模索引、专用工具、专家/湿实验验证是效果的重要来源 | 只学习控制面和证据协议，不借他人成果暗示本系统也具备同等能力 |

逐篇缺口不在本文重复铺陈，以冻结 JSON 为唯一表格源，避免 Markdown 与数据文件发生双写漂移。

这里的“否决”不是说这些机制没价值，而是说它们不能承担论文的新颖性主张。

## 4. 冻结建议：两个候选主张

### C1：Evidence Adjudication State Graph（EASG）

将科学关系从静态三元组改为可重放的证据裁决状态图。一个关系拥有不可变事件流和当前投影：

```text
candidate
  -> supported | refuted | contested
  -> accepted | needs_review | rejected
  -> superseded
```

事件至少记录 `claim_id / evidence_span / source / publication_time / condition / semantic_strength / model_disagreement / calibrated_risk / actor / config_hash`。新增证据、删除证据、出现更晚研究或人工覆核时，通过事件重新计算当前状态，而不是覆盖旧三元组。

候选 delta 不是“状态机”“证据图”或“校准”任一组件，而是：**面向科学关系入图，把字符级来源、支持/反驳、条件/时态、选择性风险和可逆裁决历史统一成可执行决策协议，并测量其对错误接收、更新正确性和审计时间的影响。**

与已有工作的主要差别必须通过下列实验而不是文案证明：

- 对照普通抽取图、带 provenance 的静态图、时序 KG 和 always-on debate；
- 删除/替换证据后，旧关系是否正确转入 contested/rejected/superseded；
- 相同覆盖率下 accepted risk 是否下降；
- 人工审计者定位错误证据的时间是否减少。

若扩大查新发现已有系统同时满足相同状态语义、字符级证据事件和评测协议，C1 必须缩小或撤回。

### C2：Evidence Literacy Tracing（ELT）

将学习者状态从“会不会某个知识点”扩展为二层状态：概念掌握 + 科研证据素养。后者至少包含：

1. 能否定位支持某个主张的原文跨度；
2. 能否区分支持、反驳、仅相关和证据不足；
3. 能否识别模态强度、条件限制和时间 supersession；
4. 能否判断多来源是否独立以及证据是否充分；
5. 能否在图谱更新后解释关系为何改变状态。

测评题从 EASG 的 accepted/contested 边生成，每道题绑定 evidence IDs；作答更新证据素养状态，随后改变解释深度、反例数量和下一题选择。候选 delta 是：**把可验证的科研证据操作能力作为知识追踪的一等状态，并用同一证据图同时约束出题、反馈和状态更新。**

必须与静态画像、传统 concept-only KT、随机题目、无 evidence binding 的 LLM tutor 比较。主指标应是预先冻结题上的证据判断准确率、校准度和延迟保持，而不是“生成文本更像个性化”。没有真实学习者或双人专家标注时，C2 只能停留在协议原型。

## 5. 支撑机制，不单列贡献

### State-Triggered Heterogeneous Adjudication

只在以下事件发生时启动 proposer–critic–judge：接近入图阈值、证据冲突、来源不独立、语义力度不匹配、状态可能 supersede。它服务于 C1 的成本—风险曲线，不再宣称“首次按需辩论”。

为避免三个角色只是同一错误的复述，正式实验至少需要一个异质维度：不同模型、独立检索池、确定性语义检查器或模型无关 hard guard。应同时报告 always-on、triggered、single-model 和 rule-only。

### Public Run Ledger + DSH Adapter

这是复现工程贡献：manifest、Git/输入哈希、模型版本、token/成本、fallback、原始输出和 verification receipt 共同构成 run。DSH 只调用同一版本化 CLI，不拥有实验真相。该机制提高可信度，但不包装成算法创新。

## 6. 研究假设与失败判据

| 主张 | 主假设 | 强基线 | 主指标 | 预先声明的失败判据 |
|---|---|---|---|---|
| C1 / EASG | 在相同 coverage 下，状态图降低错误接收并提高证据更新正确性 | 规则图、普通 RAG、静态 provenance KG、always-on debate | risk–coverage、accepted precision、错误接收率、更新准确率、ECE/Brier、审计时间 | 95% CI 与最强基线重叠且效应小；收益仅来自更高拒绝率；删除证据后状态不稳定；成本超过预算且无风险收益 |
| C2 / ELT | 证据素养状态可比 concept-only KT 更好预测并改善后续证据判断 | 静态画像、BKT/AKT/simpleKT、无绑定 LLM tutor | evidence judgment accuracy、NLL/AUC、Brier、延迟后测、专家一致性 | 仅改变主观偏好，不提升冻结题；真实学习者上无增益；题目泄露原文答案；状态不可解释或跨领域崩溃 |

所有统计以学习者/论文为独立单位；确定性重复重放不算独立样本。分类差异优先用配对 bootstrap 或 McNemar，报告效应量和 95% CI。真实实验前做 power analysis；未达到功效时只报告探索性结果。
