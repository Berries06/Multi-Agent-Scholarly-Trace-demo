# 实验设计与消融协议

目标：证明收益来自异质职责和证据约束，而不是角色数量、候选变化或页面动画。

## 1. 实验架构与已实现机制

每个机制都有配置开关、结构化输出和消融入口：

| 机制 | 开关 | 可观测输出 | 对应消融 |
| --- | --- | --- | --- |
| 句级证据溯源 | `sentence_provenance` | `claim.evidence_spans`、图谱 span 节点 | `no_provenance` |
| 多视角辩论 | `diverse_debate` | 证据、方法、外部有效性三类 `debate_views` | `no_debate` |
| 序贯可证伪检查 | `sequential_falsification` | 每条命题的轮次、测试、支持、反证与结果 | `no_falsification` |
| 校准裁判与拒答 | `judge`、`abstention` | accepted / review / rejected / abstained | `no_judge` |
| 动态学情追踪 | `knowledge_tracing` | 概念先验、后验、不确定度和下一学习焦点 | `no_knowledge_tracing` |
| 信息增益检索 | `information_gain_retrieval` | 查询加权、画像上下文与新颖度排序 | `legacy` 对照 |
| 演化、争议、空白 | `temporal_analysis` | timeline、controversies、research_gaps | `legacy` 对照 |
| 蓝海假设锦标赛 | `hypothesis_tournament` | 候选假设、多维分数、排名和待验证标记 | `no_tournament` |
| 性能探针 | `performance_probes` | 各阶段真实墙钟时间与规模计数器 | 可自定义关闭 |

“动态学情”“科研空白”“锦标赛”目前是确定性、可复现的离线算法，作用是跑通数据协议和实验路径，不是经过真实用户或大规模论文验证的最终模型。

## 2. 兼容策略

- `ScholarlyTraceOrchestrator.run()` 默认使用 `legacy`，保留原链路；
- 网页请求显式使用 `full`，评审可切换旧版与所有消融；
- 实验通过 `experiment.json` 固定预设，不在运行前改业务代码；
- `src/` 不导入 `tests/`，测试只能单向引用项目；
- 预设定义在 `src/yanhai/config.py`，真实计时在 `src/yanhai/probes.py`。

## 3. 两条评测轨道

### Track A：同候选池决策评测（当前 Demo 已实现）

所有方法接收完全相同的 24 条固定压力命题，只改变决策机制。它回答：候选质量固定时，批判者和独立裁判能否减少错误关系入图？

数据：`data/evaluation/decision_benchmark.json`。13 条命题有证据支持、11 条不支持，包含低置信真阳性、证据 ID 语义错配、元数据证据越权、类型/方向错误等固定噪声，没有随机翻转标签。

| 变体 | 决策机制 | 要验证的假设 |
|---|---|---|
| E0 普通规则程序 | 只按候选置信度阈值 | 普通程序会接收高置信错误 |
| E1 单次判定 | 置信度 + 证据 ID 存在 | 单次 Agent 无法识别证据语义和类型错误 |
| E2 同质三路投票 | 三个几乎相同阈值多数表决 | 增加同质角色不能消除共享盲点 |
| E3 提出—批判—裁判 | 反证检查后独立裁决 | 异质职责减少错误接收 |

当前结果：

| 变体 | 接收精确率 | Gold 召回 | UAR | 证据绑定护栏 |
|---|---:|---:|---:|---:|
| E0 | 0.500（11/22） | 0.846（11/13） | 1.000（11/11） | 0.818（18/22） |
| E1 | 0.611（11/18） | 0.846（11/13） | 0.636（7/11） | 1.000（18/18） |
| E2 | 0.611（11/18） | 0.846（11/13） | 0.636（7/11） | 1.000（18/18） |
| E3 | 0.846（11/13） | 0.846（11/13） | 0.182（2/11） | 1.000（13/13） |

E3 的接收精确率与 Gold 召回 Wilson 95% 区间均为 `[0.578, 0.957]`，UAR 区间 `[0.051, 0.477]`。它仍错误接收 B019、B020 两条“有效 ID 但语义错配”命题，并把 B013、B014 两条低置信真命题放入复核，故不是满分。这些数值只属于规则开发可见的压力集，不能表述为真实科学信息抽取性能。

### Track B：端到端抽取评测（提交论文前必须完成）

所有系统读取同一冻结 PDF 测试集，从实体/关系候选到最终入图全链路评测。建议基线：

- B0：词典 + 触发模式；
- B1：GLiNER + GLiREL；
- B2：SciBERT/DyGIE++；
- B3：DeepKE/OneKE；
- B4：Qwen2.5 单次结构化抽取；
- B5：最佳候选器 + 三智能体裁决。

Track B 不得使用测试集调阈值、提示词或 schema。

## 4. 正式消融矩阵

| 消融 | 固定项 | 删除/替换项 | 观察指标 |
|---|---|---|---|
| 去批判者 | 候选、裁判、阈值 | 批判输出为空 | precision、UAR、recall |
| 去独立裁判 | 候选、批判 | 提出者按自信直接决策 | 校准、错误接收 |
| 同模型三角色 | 候选与 token 预算 | 三角色共享模型/提示结构 | 与异构方案比较共享盲点 |
| 打乱证据 | 候选不变 | evidence 随机换论文 | 证据依赖性、shuffled-evidence accuracy |
| 去 schema | 文本与模型不变 | 类型约束关闭 | 类型错误率、relation F1 |
| 去图谱 | 同一论文集与生成器 | Idea 只读文本检索 | Idea 有用率、可追溯率 |
| 选择性辩论 | 模型不变 | 只在分歧/高风险边启动 | precision、时延、token 成本 |

## 5. 指标定义

```text
Accepted Triple Precision = accepted 中关系正确且证据充分的数量 / accepted 总数
Unsupported Acceptance Rate (UAR) = 被错误接收的不支持命题 / 金标准不支持命题总数
Gold Retention Recall = 被接收的金标准支持命题 / 金标准支持命题总数
Evidence Binding Completeness = accepted 中绑定至少一个有效 evidence_id 的数量 / accepted 总数
（结构护栏，不检查引用语义是否支持命题）
Evidence Span F1 = 预测证据字符跨度与金标准跨度的 micro-F1
Verified Triple Yield (VTY) = 关系正确且证据充分的 accepted 三元组数 / 论文数
```

正式实验同时报告：实体 strict/relaxed F1、关系 micro/macro F1、ECE、Brier score、平均/95 分位时延、token/显存与人工复核负担。

## 6. 实验目录与运行

| 目录 | 回答的问题 |
| --- | --- |
| `01_core_ablation` | 完整版与逐项关闭相比发生什么变化？ |
| `02_provenance_falsification` | 句级证据和反证是否真的进入裁决？ |
| `03_dynamic_knowledge` | 三种反馈能否更新难度和掌握状态？ |
| `04_query_robustness` | 不同主题和绝对化诱导查询是否被正确处理？ |
| `05_workload_scaling` | 文献扫描行数增加后，探针和输出是否稳定？ |
| `06_end_to_end_regression` | 所有 mock case 能否完整跑通？ |

运行全部实验：`python -m tests.experiments.run_all`。每次运行在 `outputs/experiments/<实验>/<时间>/` 生成 `run_config.json`、`raw_results.json`、`cases.csv`、`summary.json` 和自动生成的 `REPORT.md`。

## 7. 如何替换 mock 数据

当前 case 位于 `tests/experiments/data/mock_benchmark.jsonl`，每行至少包括：

```json
{
  "case_id": "M001",
  "profile_id": "undergraduate_ai",
  "query": "一个可复核的问题",
  "expected_terms": ["金标准概念 A", "金标准概念 B"],
  "synthetic": true
}
```

正式数据不要直接覆盖 mock 文件。新建带版本号的数据文件，记录来源、许可、标注人、复核人和金标准版本，经负责人审核后，在 `framework.py` 的数据入口显式选择该版本。

## 8. 现场展示与 Demo 讲解顺序

现场必须展示三个案例：

1. **完整方法成功**：有正确跨度且类型兼容的关系被接收，并能跳回论文和章节；
2. **基线失败、三智能体修正**：高置信但无证据/绝对化/方向错误命题被 E0/E1 接收、被 E3 拒绝；
3. **完整方法仍失败或保守**：普通共现进入 `needs_review`，或图谱 Idea 标记 `novelty_status=unverified`，说明系统不会假装全知。

Demo 讲解顺序（约 7 分钟）：选画像说明输入差异 → 启动运行展示 30 篇检索记录与证据卡链 → 解释提出/批判/裁判输入输出 → 打开压力命题展示裁判分数分解 → 展示四组同候选池对比（强调同质投票无自动增益）→ 看 2018–2025 技术脉络 → 看缺失边 Idea（强调新颖性未验证）→ 切换画像展示资源与难度变化 → 可选 OpenAlex 扩展候选并解释联网结果为何不能直接入图。

## 9. 能声称与不能声称

可以说：

- Demo 已实现可配置的多智能体研究链路；
- mock 消融、鲁棒性、反馈和扩张脚本可重复运行；
- 无裁判消融会让无证据压力命题泄漏，因此裁决门控在当前构造数据上有作用；
- 探针报告的是当前机器本地墙钟时间。

不能说：

- mock 数据证明真实幻觉率下降；
- 复制 8 条文献形成的 400 行扫描等于 400 篇真实论文；
- 启发式空白候选已被证明是新的科研方向；
- 本地亚毫秒耗时等于接入真实 LLM 后的时延；
- 没有查新就宣称机制“首创”。

## 10. 威胁与报告边界

- 24 条命题很小，且规则开发者知道错误类型，存在设计过拟合；
- 当前默认图谱使用人工转述的证据卡保证现场稳定，真实 PDF 批处理结果需独立评测；
- 当前候选器为词典/触发规则，不能代表 GLiNER、GLiREL 或 OneKE；
- 已报告二项 Wilson 95% 区间，但没有盲测、标注者一致性和重复运行，因此不写“显著提升”；
- 多智能体在共享模型、共享证据或任务简单时可能不优于单智能体。

正式 Track B 至少冻结 60 条候选关系（建议 6 篇开发阶段未见论文、每领域 2 篇），由两名标注者独立判断关系、方向与证据跨度，冲突经第三人仲裁。压力集只负责回归，不替代盲测。

## 11. 数据扩张后的验收

真实数据到齐后至少补充：

1. 50 组以上独立、人工复核的任务与证据金标准；
2. 引用是否真正支持命题的专家盲审；
3. 单 Agent、普通 RAG、无批判者、无裁判和完整系统的公平对比；
4. 均值、离散程度、置信区间和预先约定的显著性检验；
5. 失败案例、超时、费用和不利结果；
6. 数据许可、版本哈希和可复现运行清单。
