## 二、我们项目的不足（逐条，按优先级）

### P0 —— 影响赛题得分的关键差距

**1. 三智能体目前是"规则空壳"，没有任何模型调用。**
- 现状：提出者/批判者/裁判全是确定性规则函数（`agents.py`），不调用 LLM；
  论文知识抽取是"复用离线索引"，也不调用模型。
- 对标：MAKES-QA、KARMA、gpt-researcher 的核心智能体都真实调用 LLM 并做消息级协作。
- 差距：赛题 25 分创新性压的是"大模型 + 多智能体消除幻觉"，评委若发现
  "多智能体"只是三个 if-else，会直接扣分。**这是第一大差距。**

**2. 检索层单薄：单库关键词匹配，没有查询分解/多源/引文链/质量排序/自适应迭代。**
- 现状：Crossref 元数据 + OpenAlex 候选 + 本地关键词打分（`knowledge.search`）。
- 对标：ScholarFlow 的 8 节点流水线（查询分解、多源并行、引文链扩展、
  三维质检排序、自适应查询迭代、成本追踪）。
- 差距：我们检索只能命中预置 90 篇里"字面相关"的论文，无法回答
  "这篇引用了哪些关键工作""这个主题最新进展是什么"。

**3. 图谱太薄 + 检索是自研 BFS，没有社区/层次摘要/embedding。**
- 现状：19 篇证据卡 → 91 条关系；`graph_rag.py` 是自研 BFS 广度/深度/混合搜索，
  明确声明"GraphRAG-inspired、不冒充官方 runtime"。
- 对标：GraphRAG 的社区发现与层次摘要、LightRAG 的双层关键词检索。
- 差距：图谱规模与机制都撑不起"技术演化/空白发现"的深度结论。

**4. 评测没有真实金标准，赛题硬指标全是代理值。**
- 现状：24 条合成压力命题 + 合成画像，`hallucination_proxy_rate` 等三个指标
  是"工程代理指标"，`EXPERIMENT_AUDIT` 明确标为 synthetic/self-supervised。
- 对标：MAKES-QA 用 KGQA 基准评测；Paper Circle 有系统评测。
- 差距：赛题要求幻觉率<5%、适配≥85%、覆盖率≥90%，没有真实双人标注金标准
  之前，这三个数都不可信。

### P1 —— 产品化差距

**5. 学习资源是模板填充，题目是写死的。**
- 现状：导读/实操/测评由 `ResourceAgent` 模板生成，quiz 是 3 道固定题目。
- 差距：测评没有从图谱内容动态出题；"个性化"主要体现在难度档位，深度不足。

**6. 前端没有图谱/引文可视化。**
- 现状：React 界面是表格 + 时间线 + 雷达图，没有网络图。
- 对标：ScholarFlow 的 D3 引文图谱；research-assistant 的概念关联图。
- 差距：赛题"体验 15 分"要求"多智能体调度过程可视化"，图谱可视化是加分利器，
  我们现在没有。

**7. 轨迹没有成本/令牌/耗时追踪。**
- 现状：`agent_trace` 只有文字摘要和固定 duration；`/api/run/stream` 的
  `run_id` 还是 null。
- 对标：ScholarFlow 的成本追踪；gpt-researcher 的 token 统计。
- 差距：接真实模型后必须补"每个 Agent 花了多少钱/多少 token"，这是演示
  视频和作品书的硬素材。

### P2 —— 工程差距

**8. 没有 PDF→全文→抽取的自动化链路。**
- 现状：Docling/PyPDF 适配器存在但未接线；实验台只能粘贴文本；
  71 篇元数据论文拿不到全文。
- 差距：无法把新论文自动变成证据卡，知识库只能靠人工粘贴扩充。

**9. 存储是 JSON/SQLite，没有图数据库/图查询语言。**
- 现状：图谱存 JSON + SQLite 三张表。
- 对标：research-assistant 用 Neo4j。
- 差距：跨论文融合、多跳查询、图版本管理都弱；SQLite 对 90 篇够用，
  但要"真实应用"就得评估 Neo4j 或轻量图查询方案。

**10. 知识库版本与跨论文融合弱。**
- 现状：版本化语料有 registry，但跨论文实体融合只是"规范名相同即合并"。
- 对标：KARMA 的增量 enrichment。
- 差距：同一概念在不同论文中的证据冲突、时间演化没有显式表达。

## 三、改进方向速览（对应上表）

| 差距 | 改进方向 | 大概工作量 |
|---|---|---|
| 1 三智能体空壳 | 接入真实 LLM（先小模型/便宜模型当批判者与裁判），消息级协作 | 核心决策讨论后定 |
| 2 检索单薄 | 引入查询分解 + 多源检索（Semantic Scholar/arXiv）+ 引文链 + 排序 | 中 |
| 3 图谱薄 | 接入 LightRAG 式双层检索或 GraphRAG 社区；用实验台扩大证据卡 | 中-大 |
| 4 评测无金标准 | 双人标注 60+ 关系金标准（创新机制文档里已列 Track B 计划） | 团队人工 |
| 5 资源模板化 | 从 accepted 关系动态出题（把图谱三元组变测评题） | 小-中 |
| 6 无图谱可视化 | React 接 ECharts graph/力导向图，展示 evidence 边 | 中 |
| 7 无成本追踪 | 轨迹里加 token/耗时/成本字段 | 小 |
| 8 无 PDF 链路 | 接线 Docling/PyPDF：上传 PDF → 全文 → 证据卡 | 中 |
| 9 无图数据库 | 评估 Neo4j 或保持 SQLite+图算法 | 待定 |
| 10 融合弱 | 证据冲突/时间演化的显式表达 | 中 |
