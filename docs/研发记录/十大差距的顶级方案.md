## 差距 1：三智能体是"规则空壳"，没有任何模型调用（P0·命门）

**顶级方案：异质模型 + 验证器 + 校准的"三层决策"架构**

- **提出者**：GLiNER/GLiREL 生成实体/关系候选（快速高召回），LLM 只做难例补全；候选必须带 evidence_ids 与字符跨度。
- **批判者**：**独立小模型验证器**（7B/9B 级，SciFact/MultiVerS 式微调）专职做"语义蕴涵 + 时态体/情态 + 跨度覆盖"检查——正是我们在[语义漏洞笔记](决策层语义漏洞与修复线索.md)里记的 imperfective paradox 那类校验。批判者与提出者**不同模型家族**，避免"同族自证"。
- **裁判**：独立校准层——验证集上拟合的逻辑回归/小模型打分器，输出 calibrated 分数与 `accepted/needs_review/rejected`，报告 ECE 校准误差。
- 辩论 2–3 轮（批判者给反证 → 提出者修订 → 再裁决），而不是一次判定。

**参考**：KARMA、MAKES-QA、gpt-researcher；Verify Before You Commit（Qwen 2.5-7B 自查）。

**✅ 17 天落地第一步**：批判者先接一个便宜模型（如 GLM-4V-Flash 同级文本模型或 7B 开源小模型），只做"证据存在性 + 时态/绝对化断言"两类检查，其余规则保留；跑通"规则+模型混合批判"。

**🚀 完整愿景**：三个角色全部模型化、异质化，带辩论轮次与校准报告；成本控制在每轮 <1 万 token。

## 差距 2：检索层单薄（单库关键词匹配）（P0）

**顶级方案：ScholarFlow 式 8 节点检索流水线**

1. **查询分解**：多跳问题拆成子问题（IRCoT/Self-Ask 思路）；
2. **多源联邦检索**：Semantic Scholar + arXiv + Crossref + OpenAlex 并行，按 DOI 去重；
3. **引文链扩展**：向后（references）+ 向前（cited-by）各扩一层；
4. **混合排序**：BM25 粗排 → bge-m3 向量精排 → LLM 重排（取证据相关性而非字面相关）；
5. **自适应迭代**：检索后自评覆盖率不足 → 改写查询重检索（Self-RAG 式反思，最多 2–3 轮）；
6. **成本追踪**：每步记录来源、命中数、token。

**参考**：ScholarFlow（8 节点流水线）、Self-RAG、HyDE。

**✅ 17 天落地第一步**：加"查询分解 + Semantic Scholar/arXiv 多源 + 引文链一层"，排序暂用现有关键词+向量（bge-m3 本地或 API）。

**🚀 完整愿景**：全流水线 + 质量排序 + 成本面板（作品书和视频里"检索可视化"直接取材）。

## 差距 3：图谱太薄 + 自研 BFS，无社区/摘要/embedding（P0）

**顶级方案：GraphRAG BYOG 或 LightRAG 双层检索**

- **GraphRAG 路线**：Leiden 社区检测 → 层次社区报告（LLM 逐社区摘要）→ Local/Global/DRIFT 三种查询；
- **LightRAG 路线**（更快）：高低双层关键词检索 + 增量更新，索引快 10 倍；
- 两者共用：**bge-m3 向量**做实体/文本单元检索；跨论文**实体消解**用"候选对 + LLM 判定"；
- 图谱节点保持我们已有的 `paper → CONTAINS → evidence → MENTIONS → entity` 证据链（这是我们的差异化优势，保留）。

**参考**：Microsoft GraphRAG、LightRAG。

**✅ 17 天落地第一步**：选 LightRAG 路线——本地 bge-m3 给实体/证据建向量索引，替换纯 BFS；Leiden 社区（networkx）算出社区并生成 LLM 摘要。

**🚀 完整愿景**：官方 GraphRAG BYOG 接入 + 社区报告进资源生成。

## 差距 4：评测无真实金标准，三个硬指标全是代理值（P0·底线）

**顶级方案：双人标注 + 仲裁 + 冻结测试集 + 盲测**

1. **抽样**：从 3 个领域抽 60+ 条关系/证据跨度（开发集之外）；
2. **双人独立标注** + 第三人仲裁；报告 **Krippendorff's α / Cohen's κ** 一致性；
3. **冻结测试集**：标注后不再改动，开发过程不触碰；
4. **盲测**：规则基线 vs 单次 LLM vs 模型+三智能体，同池公平比较；
5. **真实三指标**：幻觉率、画像-难度适配准确率、知识点覆盖率在真实数据上计算，附置信区间与失败案例清单。

**参考**：MAKES-QA 的 KGQA 评测；本项目 `创新机制与实验.md` 的 Track B 计划。

**✅ 17 天落地第一步**：团队两人各标注 30 条关系（用实验平台导出案例），我写标注表和一致性计算脚本。

**🚀 完整愿景**：盲测 + 校准报告，成为作品书"实用价值 30 分"的实证核心。

## 差距 5：学习资源是模板填充，测评题写死（P1）

**顶级方案：图谱驱动的 grounded 生成 + 自适应测试**

- **动态出题**：从 accepted 三元组自动生成测评题（模板化 MCQ + LLM 改写干扰项），难度由学习者知识状态估计（我们知识库里就有 DKT/知识追踪论文——**用自己研究的对象做自己的引擎**）；
- **grounded 约束**：导读/实操的**每一句**都强制携带 evidence_ids（检索约束生成，无证据不写）；
- **自适应迭代**：答题正确率 → 智能体决策"降维解释"或"进阶挑战"（正是赛题要求 ③）。

**参考**：gpt-researcher 的引用约束输出；赛题"动态反馈迭代"条款。

**✅ 17 天落地第一步**：把 quiz 从 3 道写死题改成"从 accepted 三元组模板化生成"，干扰项从同类型实体池抽取。

**🚀 完整愿景**：LLM 出题 + 知识追踪难度校准 + 答题闭环。

## 差距 6：前端无图谱/引文可视化（P1）

**顶级方案：力导向图谱 + 技术演化时间线 + Agent 编排 DAG**

- **知识图谱视图**：ECharts graph（力导向）：`paper → evidence → entity → relation`，点击节点弹出证据原文跨度；accepted/rejected 用颜色区分；
- **技术演化脉络**：年份横轴，方法-任务-基准的沿革动画（我们已有 `graph_insights` 时间线数据）；
- **多智能体编排视图**：LangGraph Studio 式 DAG——5 个 Agent 节点流式点亮、边上是数据传输、点击看输入输出。

**参考**：ScholarFlow 的 D3 引文图谱；LangGraph Studio。

**✅ 17 天落地第一步**：接 ECharts graph 画出单领域"证据链图谱"（数据后端已有），加点击看证据。

**🚀 完整愿景**：三视图联动 + 流式编排动画（10 分钟演示视频的核心镜头）。

## 差距 7：无 token/成本/耗时追踪（P1）

**顶级方案：run 级可观测（Langfuse/OpenTelemetry 式）**

- 每个 Agent 记录：输入/输出 token、墙钟耗时、模型、成本（多模型价目表折算）；
- run 级串联：request_id → run_id → 每个 Agent span → 汇总面板；
- 预算熔断：单轮成本上限，超限降级到小模型或规则；
- 前端展示"本次运行花了 ¥0.023 / 3200 token"。

**参考**：ScholarFlow 成本追踪；Langfuse；OTel GenAI 语义约定。

**✅ 17 天落地第一步**：`agent_trace` 加 token/耗时/成本字段，`/api/run/stream` 的 run_id 贯通（现在还是 null）。

**🚀 完整愿景**：全链路 tracing + 成本看板 + 预算策略。

## 差距 8：无 PDF→全文→证据卡自动化链路（P2）

**顶级方案：Docling + GROBID 双解析 → 证据卡 → 人工复核队列**

- **解析**：Docling（布局感知，表格/公式）为主，GROBID（书目结构/引文）为元数据源；
- **抽取**：解析结果直接进我们已有的 `SchemaGuidedExtractor` → 证据卡候选；
- **复核**：所有自动结果进 `needs_review` 队列，人工一键确认/修改后入图（人类在环）；
- 批量任务：上传 N 篇 → 进度条 → 审计报告（来源、许可、失败重试）。

**参考**：Docling、GROBID（我们 README 已声明路线）。

**✅ 17 天落地第一步**：实验台加"上传 PDF"（PyPDFParser 已有），解析后自动填进粘贴框跑抽取。

**🚀 完整愿景**：批量摄入 + 复核队列 + 71 篇元数据论文全部变证据卡。

## 差距 9：存储是 JSON/SQLite，无图查询（P2）

**顶级方案：SQLite 主存 + 图查询层抽象 + 可选 Neo4j**

- 保持 SQLite 作为**唯一事实源**（离线、零依赖、可交付）；
- 之上抽象图查询层（多跳路径、社区、演化查询用 networkx 算法实现）；
- 提供**可选 Neo4j 适配器**：导出 Cypher，可视化与多跳查询走图数据库，正式部署可切换；
- 数据契约不变（nodes/edges/evidence_ids），存储可替换。

**参考**：research-assistant 的 Neo4j 用法。

**✅ 17 天落地第一步**：把现有图查询收口到一个 `GraphQuery` 接口（现在是散在各处的 BFS），SQLite 实现先行。

**🚀 完整愿景**：Neo4j/AGE 适配器 + 图算法库（PageRank/社区/最短路径）上线。

## 差距 10：跨论文融合弱（同名即合并），无冲突/演化表达（P2）

**顶级方案：证据冲突建模 + 时序知识图谱 + LLM 辅助实体消解**

- **冲突显式化**：同一概念的多篇论文主张带 `stance`（support/contradict）+ 论文年份，图上直接查询"谁与谁矛盾"；
- **时序演化**：边带时间戳，"技术演化脉络"从"按年份排序"升级为真正的时序查询（方法 A 在 2020 提出、2022 被 B 改进）；
- **实体消解**：候选对（embedding 相似 + 名称规则）→ LLM 判定是否同义 → 合并但**保留各自 provenance**（永远可回溯到原文）；
- 图谱版本化：每次更新留版本快照，可对比"图怎么演化的"。

**参考**：KARMA 的增量 enrichment；时序知识图谱（TKGC）研究。

**✅ 17 天落地第一步**：给 relation 加 `paper_year` 与 `stance` 字段，`graph_insights` 时间线改从字段读而非临时排序。

**🚀 完整愿景**：冲突检测自动标记争议点 → 争议本身就是"研究空白 Idea"的高质量来源。
