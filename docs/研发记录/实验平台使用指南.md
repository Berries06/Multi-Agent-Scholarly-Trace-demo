# 实验平台使用指南（团队亲手做实验）

> 目标：让每位成员都能**亲手输入论文、跑通流水线、看到每一步中间量**，
> 用真实领域论文验证 AI 生成代码是否可信，并把每次实验沉淀成可回归的测试数据。

## 1. 为什么需要实验平台

Codex/AI 生成的代码在中文领域论文上会暴露"语义漏洞"（不是语法错，而是对
时态、别名、共现等深层语义理解偏了），无法靠一次性 review 找全。实验平台
把整条流水线拆开，让成员在每一层亲眼核对中间量，把"AI 黑盒"变成"可逐步
验收的白盒"。

## 2. 四个实验台一览

| 实验台 | 文件 | 覆盖阶段 | 成员要回答的问题 |
| --- | --- | --- | --- |
| 论文抽取 | `extraction_lab.py`（端口 8503） | 结构解析 → 实体/关系/证据抽取 | 抽取的实体、关系、证据跨度对不对？ |
| 端到端流水线 | `pipeline_lab.py`（端口 8504） | 解析 → 抽取 → 学情诊断 → 三智能体 → 资源 | 整条链路每一步是否合理、最终资源是否可信？ |
| 证据裁决 | `shared_evidence_decision_lab.py`（端口 8501） | 提出/批判/裁判（手写案例调参） | 给定参数下裁决是否符合预期？ |
| GLiNER 实体 | `gliner_entity_lab.py`（端口 8502，需 GPU） | 零样本实体抽取（模型） | 规则抽取与模型抽取哪个更贴合领域？ |

## 3. 环境准备（一次性）

```powershell
# 用项目里已有的 .venv-lab（Python 3.12.13，已装 streamlit）
# 或新建：python -m venv .venv-lab; .venv-lab\Scripts\python.exe -m pip install streamlit==1.60.0
$env:PYTHONPATH="src"
```

## 4. 启动与用法

```powershell
# 论文抽取实验台
.venv-lab\Scripts\python.exe -m streamlit run extraction_lab.py --server.address 127.0.0.1 --server.port 8503
# 端到端流水线实验台
.venv-lab\Scripts\python.exe -m streamlit run pipeline_lab.py --server.address 127.0.0.1 --server.port 8504
# 证据裁决实验台（需设置共享密码）
$env:LAB_SHARED_PASSWORD="本地临时密码"
.venv-lab\Scripts\python.exe -m streamlit run shared_evidence_decision_lab.py --server.address 127.0.0.1 --server.port 8501
```

浏览器打开对应 `http://127.0.0.1:850x/`。粘贴论文正文（Markdown，`#` 分段），
逐层展开查看中间量；页面底部有"完整 JSON 下载"，用于存档。

## 5. 一次标准实验的验收点

以「论文抽取」为例，成员应逐项核对：

1. **结构解析**：章节切分是否合理（标题是否被正确识别）；
2. **实体**：类型（METHOD/TASK/DATASET/METRIC/FINDING/LIMITATION/DOMAIN）是否
   判对，规范名是否统一，别名是否归并到同一个实体；
3. **证据跨度**：`char_start/char_end` 是否精确落在原文对应位置；
4. **关系候选**：`status`（accepted / needs_review / rejected）与批判项是否合理；
   尤其注意"同句共现不能自动升级为关系"是否被正确标记；
5. **护栏**：无证据的绝对化命题（如"guarantees/proves"）是否被拒绝。

## 6. 如何积累测试数据（对应赛题"测试数据"要求）

赛题实用价值要求"至少 1 个垂直领域知识库 + 不少于 3 组画像测试用例"。做法：

1. 每个成员准备 3–5 条自己领域的真实论文片段（含**期望实体/关系/证据跨度**）；
2. 用实验台跑出实际输出，逐条比对期望，标记 `正确 / 误拒 / 误收 / 待议`；
3. 把比对结果按固定格式存档（可参考 `tests/experiments/` 的案例结构），
   并记录标注人、来源、金标准版本；
4. 汇总后得到"抽取/裁决正确率"的初步判断——这就是实用价值指标的真实来源。

> 重要：不要用 AI 自拟样本冒充成员样本。实验台故意**不内置**语义测试案例，
> 任何带"示例/占位"字样的样例都只用于熟悉界面，不计入验收。

## 7. 与产品后端的关系

实验台的端到端逻辑已抽成 `src/yanhai/fresh_pipeline.py`，FastAPI 后端的
`POST /api/ingest-paper` 复用同一逻辑。因此成员在实验台里验证过的流程，
就是产品后端"粘贴论文 → 完整流水线"的同一套代码，验证结论可直接迁移。
