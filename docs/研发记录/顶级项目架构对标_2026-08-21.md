## 二、不能只学“模块”，要学共同架构规律

### 1. 控制面与数据面分离

成熟项目不会让某个页面或聊天会话成为唯一状态源。实验配置、运行状态、原始产物和评测结果独立保存，UI 只是投影。研海寻踪应把 DSH 定位为控制入口，把仓库内 run registry 定位为实验事实源。

### 2. Agent 必须拥有独立信息或工具

Virtual Lab、SciToolAgent、OpenScholar 的角色之所以有意义，是因为不同节点拥有不同工具、证据或决策责任。三个相同模型重复提示不等于三种独立证据。研海寻踪的提出者、批判者、裁判必须在输入、模型或可验证约束上异质。

### 3. 原始证据和中间工件是一等公民

OpenScholar、PaperQA2、SciAtlas、HippoRAG 和 DeepResearch Bench 都把检索结果、上下文、配置或原始输出暴露出来。我们的优势应进一步做到字符跨度、章节、来源、决策轨迹与关系版本共同可回溯。

### 4. 查询策略必须按问题类型路由

GraphRAG 的 Local/Global/DRIFT、PaperQA2 的 agentic tool order、Open Deep Research 的 supervisor decomposition 都说明单一检索策略不够。研海寻踪需要区分事实查询、跨论文综合、演化、争议与个性化学习任务。

### 5. 公开复现不是附录，而是产品能力

最值得直接学习的不是某个 Agent prompt，而是 HippoRAG 的 reproduce 目录、DeepResearch Bench 的原始输出协议、Agent Laboratory 的 YAML 配置、SciAtlas 的 run artifacts 和 Virtual Lab 的完整讨论/计算分数发布方式。

## 三、对研海寻踪架构的直接决策

1. 不整包引入 LangGraph/GraphRAG/LightRAG；先建立稳定的 `ExperimentManifest`、`RunRecord`、`Retriever`、`GraphQuery` 和 `ExecutorAdapter` 接口。
2. SQLite 保持唯一事实源，图与向量系统是可重建索引；任何外部框架都必须消费同一 evidence contract。
3. 查询层增加 task router：local evidence、global synthesis、controversy、evolution、learning 五类模式。
4. 多 Agent 改为事件和状态驱动：candidate → critiqued → adjudicated → guarded → accepted/needs_review/rejected，可重放、可人工覆盖。
5. 实验平台先实现 manifest/registry/raw outputs/failure cases，再做漂亮的 Experiment Ledger。
6. 前端第一屏展示证据状态与真实/代理指标标签，不再展示来源不明的单个百分比。

## 四、下一轮审计要求

- 对每个项目再读论文的 method、experiments、limitations 或 responsible-use 部分；
- 将可学习模式映射到具体本地文件与接口；
- 核验许可证、模型/数据依赖和复现实验成本；
- 用至少 100 篇论文的局限证据修订候选创新；
- 任何“首创/首次/显著优于”必须经过独立查新和本项目实验，不从本表直接推出。
