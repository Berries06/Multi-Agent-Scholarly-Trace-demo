# 文献管线升级方案：搜索渠道、切分与入库（2026-08-23）

> 触发：学习 ScholarAgent4SC（CAAI 社计智能专委会的论文订阅系统，[原文](https://mp.weixin.qq.com/s/ahOauC8ih4sgD02-XtWZkA)）+ 本次 30 篇调研 + 缺口矩阵 §24.5 已列的九项系统综述缺口。
> 目标：把我们的文献工作从"一次性的 100 篇审计"升级为"持续追踪 → 自动初筛 → 结构化切分 → 可裁决入库"的流水线。**原则不变：AI 生成内容不入图，一切入图关系必须过裁决链。**

## 1. ScholarAgent4SC 做到了什么（学到的设计）

| 它的能力 | 设计要点 | 我们的对应 |
|---|---|---|
| 每周自主追踪 arXiv 社会计算方向 | 定时自动检索（类别+关键词） | 只有一次性脚本，无定时 |
| 每周精选 Top 10 | 固定数量的"值得读"筛选，控制信息噪声 | 无筛选排名，审计语料是手工挑选 |
| 四问解读（研究什么/什么场景/方法差异/创新判断） | 结构化解读模板，逼 AI 输出可核验字段 | 证据卡已有类似字段，但无批量解读流程 |
| "创新/改进"标签（与相似工作匹配） | 新颖性初筛 = 与已有文献库比对 | 我们有 100+2 篇冻结语料，但没做自动匹配 |
| 邮件推送周报 | 稳定分发渠道 | 无 |
| PDF/Code 链接、已中稿标识、第一作者机构 | 元数据完备化，降低后续核对成本 | manifest 已有部分字段，缺"已中稿/机构" |

**它没做到（也是我们更该做的）**：它的解读是"AI 转述"，没有字符级证据跨度、没有人工复核队列、不进入可裁决的知识图谱——这正是我们的 EASG 闭环能补上的部分：**周报产出只进 candidate 队列，人工确认 + 裁决链通过后才入图。**

## 2. 搜索渠道升级

**现状**：`sources.py` 四源（arXiv/OpenAlex/Crossref/SemanticScholar）+ 官方文档目录；`audit_literature_corpus.py` 一次性审计；`expand_vertical_corpora.py` Crossref 扩量。

**升级设计（P0/P1）**：

| # | 动作 | 说明 | 阶段 |
|---|---|---|---|
| S1 | 每周扫描脚本 `scripts/weekly_literature_scan.py` | arXiv API：三个类别（cs.CL/cs.AI/cs.SI）+ 三组关键词（evidence adjudication / KG construction+LLM / multi-agent verification），只取最近 7 天；OpenAlex/S2 按 DOI 补全元数据；检索式与结果快照落盘 `data/vertical_kb/search_cache/<date>/`（沿用现有 cache 模式，满足"检索可复现"） | P0 |
| S2 | 去重与增量 | 去重键 DOI>arXiv ID>规范化标题（已有逻辑复用）；与已入 corpus/vertical_kb 的论文集合比对，只输出新增 | P0 |
| S3 | 新颖性初筛（"创新/改进"标签） | 对每篇新增论文生成四问解读 + 与 100+2 篇语料做相似度匹配（标题/摘要向量 + LLM 判定"与哪些已有工作最接近"），输出 `candidate|novel` 标签；**标签只是初筛线索，最终由人复核**（对应 L004 检索饱和门的人工部分） | P0（LLM 判定用便宜档模型，不阻塞） |
| S4 | 周报 | 输出 `docs/文献周报/weekly_YYYYWW.md`：Top10 表（题目/机构/中稿状态/摘要/四问解读/创新-改进/链接）+ 未入选候选全量清单；先本地文件，9-05 后接邮件（smtplib 脚本 + 订阅名单文件，不进 git） | P0 本地 / P1 邮件 |
| S5 | 引文链滚动补查 | 对每篇入选论文自动拉 references + cited-by（S2 API），只记录"为什么引它"一句（缺口矩阵 §24.5 第 7 条） | P1 |

## 3. 收集后如何切分

**现状**：`PlainTextParser` 按章节切分（论文级 sections）；`extraction.py` 句子级切分带全局字符偏移（`_sentence_spans`），已有 tests 锁定全局偏移契约。

**升级设计**：

| # | 动作 | 说明 | 阶段 |
|---|---|---|---|
| C1 | 统一"块"标准：句子级 span，切块不割裂句子 | 以现有 `_sentence_spans` 为唯一切分单元；块 = 连续 N 句（默认 8，重叠 1），每块带 `paper_id/section/sentence_ids/char_start/char_end`；证据抽取仍指向句子级 span，块只用于检索与 LLM 上下文 | P0（复用现逻辑，新写 `scripts/chunk_corpus.py`） |
| C2 | 元数据完备化 | 每篇候选卡补齐：第一作者机构、已中稿 venue、PDF/Code 链接、许可、source_verified_against_original、`candidate|evidence_card` 状态（对齐 manifest 现有字段） | P0 |
| C3 | 表格/图表标记 | pypdf 层无法可靠解析表格：切块时对含表格/图区域的块打 `needs_human_ocr` 标记，不猜内容（证据卡技能纪律） | P0 |
| C4 | Docling/GROBID 结构化 | 作为可选依赖后置：换更高质量的结构化（section 树 + 表格），不阻塞 9-05 | P1 |

## 4. 如何进入知识库（三态摄入协议）

**现状**：manifest 分 `evidence_card`(8) 与 `metadata_only`(22)；extraction 生成 evidence/relations 均带 evidence_ids；SQLite rebuild 离线重建；online 查询走内存图。

**升级设计**：

```text
metadata_only（只有书目信息，绝不产生证据）
  → candidate（全文已取 + 已切块 + 有四问解读 + human_review_required=true）
  → evidence_card（双人复核解读、标注证据句、哈希冻结）
  → 入图（经 EASG 裁决链：提出→批判→裁判→accepted 才写 relations）
```

| # | 动作 | 说明 | 阶段 |
|---|---|---|---|
| I1 | 候选队列文件 | `data/vertical_kb/candidate_queue.json`：周报产出的解读卡与切块元数据全部先落此队列，带 `human_review_required=true`；**任何 AI 解读文本不得直接变成 evidence** | P0 |
| I2 | 复核→升级 | 复核者确认后，把该篇从 metadata_only 升 evidence_card：填 `source_verified_against_original=true`、复核人、日期，重算 manifest 哈希 | P0 |
| I3 | 入图走裁决链 | evidence_card 的正文经 SchemaGuidedExtractor 抽取 → Proposer/Critic/Judge 裁决 → accepted 关系入图（现有链路已具备，仅把"周报论文"接进同一入口 `scripts/extract_knowledge.py`） | P0 |
| I4 | 周报解读与图谱证据分离 | 周报里的"四问解读"是**阅读辅助**，不是**证据跨度**——它单独存 candidate 卡的 interpretation 字段，与 evidence_span 字段严格分离，防止 AI 转述冒充原文证据（本项目的核心纪律） | P0 |

## 5. 与现有体系的关系（避免重复建设）

- 六套公开实验协议、MLflow、verification 收据不因本方案改变；
- `audit_literature_corpus.py` 保持冻结（100 篇已发布哈希不动）；新论文走 candidate_queue，不进 corpus 冻结表；
- L004（引文链、专利与检索饱和门）的自动化部分由 S2/S5 承担，人工纳排与签字不变；
- 判重、新颖度标签全部标记"线索级"，最终口径以人工复核为准（延续"AI 生成默认可疑"纪律）。
