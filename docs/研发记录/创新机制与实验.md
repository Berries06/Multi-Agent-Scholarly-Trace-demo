# 当前三智能体实验架构

版本：P0 收口版（2026-08-14）

## 1. 唯一受支持的运行协议

当前业务运行时只保留三个核心决策 Agent：

1. **提出者**：从版本化证据与图谱中组织候选关系；
2. **批判者**：检查证据存在性、跨度、类型、方向和过度声明；
3. **裁判**：独立输出 `accepted / needs_review / rejected`。

论文知识抽取和用户意图感知属于两个前置专职 Agent；画像诊断、图检索和资源生成属于服务层，不再用角色数量包装成“六智能体”。

旧 `legacy/full/no_*` preset、序贯反证、动态知识追踪、假设锦标赛和旧性能探针已移至 `src/yanhai/archive/legacy_six_agent.py`。归档代码仅用于解释历史报告，不得进入新实验或当前产品口径。

## 2. 两类实验模式

| 模式 | 输入 | 变体 | 能回答的问题 |
| --- | --- | --- | --- |
| `decision_ablation` | 24 条冻结 Track A 候选命题 | `rule_program`、`single_pass`、`homogeneous_vote`、`evidence_triad` | 在候选池不变时，异质批判与裁决是否减少错误接收 |
| `orchestrator` | 9 条 synthetic proxy 查询、3 组合成画像 | `three_agent_pipeline` | 当前画像—图检索—三智能体裁决—资源生成协议是否可重复运行 |

`experiment.json` 必须显式声明 `mode` 和 `variants`。框架会拒绝仍含 `presets` 的旧配置，避免历史六智能体实验被误当成当前结果。

## 3. 六组实验

| 目录 | 评估类型 | 当前问题 |
| --- | --- | --- |
| `01_core_ablation` | `synthetic_proxy` | 四种 Track A 决策机制在同一 24 条候选池上的差异 |
| `02_provenance_falsification` | `synthetic_proxy` | 证据缺失、元数据越权、语义错配、过度声明与方向错误的失败模式；目录名为历史兼容名称 |
| `03_dynamic_knowledge` | `self_supervised_proxy` | 三种反馈下目标难度、适配指标和三智能体轨迹是否稳定；不再声称运行动态知识追踪 Agent |
| `04_query_robustness` | `synthetic_proxy` | 不同主题与绝对化诱导查询是否保持证据约束 |
| `05_workload_scaling` | `simulation_only` | 重复扫描行增加时，排除固定 24 案例消融后的核心管线墙钟耗时、P95 和结果格式是否稳定 |
| `06_end_to_end_regression` | `simulation_only` | 9 个合成 case 是否完整通过当前三智能体协议 |

运行完整配置：

```powershell
python -m tests.experiments.run_all
```

CI 冒烟配置：

```powershell
python -m tests.experiments.run_all --repetitions 1 --output-root .tmp/ci-experiments
```

每次运行在独立时间目录生成：

- `run_config.json`：冻结配置、评估类型、主张上限、代码/输入哈希、Git 状态、运行环境、计时范围和 UTC 时间；
- `raw_results.json`：逐次、逐案例结果；
- `cases.csv`：可审计的表格输出；
- `summary.json`：按变体、倍率与反馈汇总；
- `REPORT.md`：自动报告与完整性边界；
- `verification.json`：raw→summary、raw→CSV、summary→report 全量一致性校验的通过状态与五份文件 SHA-256。

## 4. 数据性质

Track A 使用版本化开发压力集；它有标签，但不是独立盲测或公开基准。查询回归使用 `tests/experiments/data/mock_benchmark.jsonl`，每条都必须显式包含 `"synthetic": true`。

当前按实验目的分别分类为 `synthetic_proxy`、`self_supervised_proxy` 或 `simulation_only`；六组实验均不属于 `real_gt` 或 `human_eval`：

- 可以证明代码路径、协议字段、错误护栏和重复运行可复现；
- 不能证明真实幻觉率下降、模型准确率提升或跨领域泛化；
- 重复次数、数据倍率和扰动次数不能计为新的独立样本。

正式数据不得覆盖 mock 文件。应新建带版本号的数据文件，并保存来源、许可、标注人、复核人、仲裁状态和金标准版本。

## 5. 下一阶段 Track B

正式结论至少需要：

1. 6–10 篇开发阶段未见的合法全文；
2. 不少于 60 条关系及证据跨度；
3. 两名标注者独立标注、第三人仲裁及一致性统计；
4. 规则、真实候选模型、单次 LLM 和最佳候选器 + 三智能体的公平比较；
5. 实体/关系/证据 F1、接受精确率、召回、UAR、校准、时延和成本；
6. 失败案例、置信区间、数据版本哈希和完整复现清单。
